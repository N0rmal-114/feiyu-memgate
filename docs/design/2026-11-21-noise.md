# 无关的记忆：按分数过滤不管用，换两个办法

状态：只有测量。测量用的脚本是 `bench/chat/model_lab.py`、`bench/chat/session_lab.py` 和它们共用的 `bench/chat/noise.py`（实验用，不是产品代码），题目是 [bench/chat](../../bench/chat/README.md)。

## 问题

前面几篇记录里反复出现同一件事：交给模型的记忆里，和当下那句话有关的是少数。单句闲聊每句交 4.3 条，相关的不到四成；一段对话里每轮新到 3.4 条，相关的不到四分之一；和任何记忆都无关的闲话，十次有九次也带了东西。之前所有的改动都是在往上加。

## 先试的：按分数过滤

四种规则，都只从产品现在会交出去的记忆里往下拿（开发集，bge-m3，`broad` 档）：

| 规则 | 做法 | 结果 |
|---|---|---|
| 给“跟谁都近”的记忆降权 | 一条记忆和它最近的 k 条别的记忆的平均相似度，高出全库中位数的部分乘一个系数，从它的分数里扣掉 | 排序好了一点（单句题 `direct` 52.8 到 56.2，6 句进、1 句出；安静 12.5 到 18.8），但空出来的位置被别的记忆补上：每句的无关条数 2.78 到 2.58，会话里每轮 2.65 到 2.61，基本没少 |
| “有没有哪条明显突出” | 这句话对全库每条记忆的相似度算均值和标准差，最高的那条不够突出就什么都不交 | 最差。用“最突出的程度”区分该安静的闲聊和联想闲聊，ROC-AUC 只有 0.66，还不如直接看最高分（0.83）；门槛一提就大量误伤（会话里 28 轮该有的记忆没了） |
| 话题在继续时提高门槛 | 这一轮最相关的那条历史里已经有了，新的记忆要和它差不多相关才交 | 每轮少 0.3 条无关的，丢 8 到 11 轮该有的记忆 |
| 每轮新增设上限 | 对话第二轮起每轮最多新交 3 条 | 唯一划算的一项：每轮无关的 2.65 到 2.31，只丢 2 轮。上限 2 条就要丢 21 轮 |

组合起来也没有更好。原因是相关和无关的记忆在分数上本来就叠在一起：联想要找的正是“相似度不高但有关”的记忆，放它们进来的同一道门也放进了无关的。分数在 0.5 以上的，相关的记忆里有 53%，无关的里有 26%，这样的间隔过滤不出干净的结果。

## 危害有多大

换一个问法：无关的记忆交过去之后，模型到底用没用。用已有的回复来量，回复和一条记忆有一段相同的字句（至少 3 个字，和对话池判断“提到”是同一条规则）就算“用了”。写回复的是一个小模型（Claude Haiku），给它的说明里已经写着“无关的不要硬提”。

| | 开发集 | 留出集 |
|---|---|---|
| 联想闲聊：拿到了无关记忆的回复里，用了无关记忆的 | 36.5% | 30.1% |
| 该安静的闲聊：拿到了记忆的回复里，用了的 | 50.0% | 63.2% |
| 联想闲聊：拿到了相关记忆的回复里，用了相关记忆的 | 89.9% | 83.6% |

三成以上的回复把不相干的事扯了进来；该安静的时候，一半以上。

## 管用的两个办法

四种交法在开发集上比过，两种留下来在留出集上各验证一次：

**一、把说明写严。** 不动交过去的记忆，只改说明：告诉模型这些记忆大多和这句话无关，只有明显有关的才用，拿不准的一律不提。

| | 开发集 | 留出集 |
|---|---|---|
| 联想闲聊：用了无关记忆 | 36.5% → 12.7% | 30.1% → 6.5% |
| 该安静的闲聊：用了无关记忆 | 50.0% → 4.8% | 63.2% → 2.6% |
| 联想闲聊：用了相关记忆 | 89.9% → 77.1% | 83.6% → 69.8% |

硬用无关记忆的情况降到原来的三分之一到五分之一，该安静时几乎不再乱提。代价是相关的记忆也少用了一些，从八九成降到七成上下。

**二、让模型先挑。** 回复之前多一步：把这句话和候选的记忆交给一个小模型，让它挑出“朋友听到这句话会想到的”，只把挑中的交下去。

| | 开发集 | 留出集 |
|---|---|---|
| 每句闲聊交出去的记忆 | 4.29 → 1.66 | 4.24 → 1.80 |
| 其中相关的占比 | 35.3% → 79.9% | 36.2% → 77.6% |
| 相关的记忆留下了 | 87.6% | 91.0% |
| 无关的记忆留下了 | 12.0% | 14.9% |
| 直接相关的那条：候选里有，挑完还在 | 76 次里 75 次 | 89 次里 87 次 |
| 该安静的闲聊一条都不留 | 83.3% | 66.7% |

小模型分得清哪些有关，包括字面不像、靠常识才连得上的。分数做不到的区分，它看一眼就做到了。代价是每一轮在回复之前多一次模型调用。

没有留下来的两种（只在开发集上量过）：按分数把记忆分成“很可能有关”和“多半无关”两档，相关的记忆常常分数不高、被归进第二档，模型就不用了（用了相关记忆的从 89.9% 掉到 59.6%）；只给分数最高的 3 条，硬用无关记忆的比例不降反升（46.1%），模型手里的记忆少了，每一条反而更容易被用上。

## 这说明什么

降低无关记忆的危害，杠杆不在检索的分数上，在交给模型的那一步：怎么说，或者交之前让模型看一眼。检索这一侧能做的是把候选找全（前几篇记录），以及每轮新增的上限这类不贵的限制。

## 限制

- 写回复、做挑选的都是同一个小模型，闲聊和记忆也是语言模型写的。别的聊天模型对同一句说明的反应可能不同，没有量过。
- “用了”是按字面重合判断的：换了说法的引用算不上，碰巧重合的三个字会算上。几种交法之间的比较比单个数字可靠。
- “把说明写严”量的是给写回复的模型的一段任务说明，不是记忆块里的那句话本身；做进产品时措辞要重写，效果要重新看。
- “让模型先挑”量的是挑得准不准，没有量加上这一步之后整轮变慢多少、多花多少。挑选是成批做的，同一批里有别的题目（每个世界两道，互相拿不到对方的答案）。
- 没有在真实的聊天里验证过。回复本身好不好，这里仍然没有量。
