# 受众级别：存储给谁看，客户端被谁看

状态：已实现。改的是配置和启动时的检查，不改存储格式，不改请求的字段，不需要模型。

## 问题

一个客户端能读哪些存储，由它配置里的 `recall` 名单决定，这份名单以前没有人检查。`public = true` 只是换了一套更严的脱敏，并不限制这个客户端能读什么。把放私聊记忆的存储写进群聊客户端的名单，网关照常启动，私下说的话就会出现在群里。

[安全说明](../security.md)里一直写着第一道线是“不让公开客户端读到放私事的存储”，脱敏是第二道线。第二道线有启动检查（公开客户端没有脱敏步骤时拒绝启动），第一道线没有。

## 做法

配置里多说两件事，启动时核对它们对不对得上。

**级别。** 三级，从窄到宽：`owner`（只给主人）、`group`（给一个群的成员）、`public`（谁都可以看）。

- 存储的受众：里面的内容最多可以给谁看。`[stores.<名字>]` 和 `[tenants.<名字>]` 里写 `audience`。
- 客户端的受众：它拿到的内容会被谁看到。`[clients.<名字>]` 里写 `audience`。

**两条规则。**

1. 客户端只能把受众不比自己窄的存储写进 `recall`。主人级的客户端什么都能读；群级的客户端能读群级和公开的存储；公开的客户端只能读公开的存储。
2. 带租户的群级客户端同时服务很多个群。一个共享的存储如果声明是 `group`，它属于其中一个群，所以这样的客户端不能读它：它读的共享存储必须是 `public`。`"@tenant"`（每个群自己的存储）不受这条限制，它的受众是租户来源的受众。

对不上时网关拒绝启动，错误里写明是哪个客户端、哪个存储、各自是什么级别，以及两种改法：把存储从名单里拿掉，或者在确认里面的内容都可以给这些人看之后改存储的声明。

**没有声明时。** 存储默认 `owner`，租户来源默认 `group`。客户端不写 `audience` 时，不公开的是 `owner`；公开的，带租户是 `group`，不带租户是 `public`。只写 `audience` 不写 `public` 时，`public` 由它推出；两个都写而互相矛盾时拒绝启动。

默认值都取最严的一边。代价是已有的配置里，公开客户端读着的存储必须补一行声明，否则升级后启动不了。这是有意的：检查的目的就是让“这个存储可以给外人看”成为一句写下来的话，而不是名单里顺手多写的一个名字。

**在代码里建的网关。** 检查放在 `Gateway` 里，不放在读配置文件的地方，所以直接用 `Gateway(...)` 建的网关（嵌入式用法）和从文件建的走同一套规则，级别通过 `audiences=` 传入。

## 考虑过没有做的

- **只给存储分级，客户端沿用 `public` 这一个开关。** 这样分不清“一个群的机器人”和“直播间”：两者都是 `public = true`，但前者可以读这个群的存储，后者不可以。所以客户端也要有自己的级别。
- **没有声明的存储不检查，只在 `check` 里提醒。** 这样只有主动写了声明的人受保护，而会把私聊存储误写进群聊名单的，多半正是没有写声明的配置。
- **按受众限制写入。** 整理“可公开清单”的客户端本来就是主人级的客户端往公开的存储里写，这是正当用法，拦不得。反方向（给别人看的客户端往主人级的存储里写）不会泄露主人的记忆，但别人说的话会进到私聊的记忆里，`feiyu-memgate check` 对这种配置给一行提醒，不拒绝启动。
- **每个请求再查一次。** 客户端的权限在网关建好之后不再变，启动时查过就够，请求路径没有加东西。召回步骤可以从 `ctx.audience` 读到这次请求的客户端是哪一级。

## 检查了什么，没检查什么

检查的是声明之间对不对得上。声明本身由部署的人负责：一个存储写了 `public`，网关就当它可以给任何人看，不会去看里面的内容。存储里的单条记忆没有自己的受众，同一个存储里的内容是同一级。

## 一起做的两件小事

- **客户端可以发送 `context`。** 请求里的 `context` 网关一直接受，并交给每个召回步骤和写入守卫，但两个 Python 客户端和 DSH 插件都不发。现在都可以发，约定了三个常用的键：`channel`（对话发生在哪里）、`chat`（`private` 或 `group`）、`via`（是什么触发了这次请求）。网关自带的步骤不读它，它也不能当作身份使用；自己写的步骤和守卫可以用。
- **AstrBot 示例里的主人编号带平台前缀。** 以前只比对发送者的编号，同一个号码在另一个平台上是另一个账号，却会被当成主人。现在写成 `平台:编号`，没有前缀的条目不再生效，启动时给一行警告。

## 测试

`tests/test_audience.py`。核心是一张手写的表：六种客户端（主人级、主人级带租户、群级带租户、群级不带租户、公开不带租户、公开带租户）乘以八种名单条目（共享存储的四种声明，`"@tenant"` 的四种声明），每一格写明该放行还是该拒绝，从配置文件和从代码两条路各建一次网关核对。表是照规则手写的，不是调用实现算出来的。

放行的每一格再做一次端到端的核对：主人级的客户端往主人级的存储里写一条带记号的记忆，这一格的客户端去召回，结果里不能有来自那个存储的条目，也不能出现记号。仓库里的每个示例配置也过一遍：受众不是主人的客户端，读到的存储没有一个是主人级的。
