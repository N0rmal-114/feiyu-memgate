# 回复本身有没有变好：盲评的成对比较

状态：只有测量。量的是 DSH 插件里几项实验设置对回复的影响，设置都默认关。测量用的脚本在 [bench/chat/replies](../../bench/chat/replies/)（实验用，不是产品代码），会话题是 [bench/chat](../../bench/chat/README.md) 里开发集每个世界的 `sessions`。只用了开发集。

## 问的是什么

前面几篇记录量的是两件事：记忆有没有摆到模型面前（[多轮对话里的召回](2026-11-18-sessions.md)），以及回复和记忆有没有一段相同的字（[无关的记忆](2026-11-21-noise.md)）。两篇都在“限制”里写了同一句：回复本身好不好，没有量。这一篇问的就是这件事：换一种给记忆的办法之后，回复有没有变好或变差。

## 怎么量的

开发集的 36 段写好的会话（12 个世界各 3 段），284 轮。每个配置把会话回放一遍，每一轮得到一份交给写回复一方的材料：人设、这段对话到此为止的内容、主人的话、记忆块。记忆块的措辞由插件自己的 `block.js` 生成；前几轮给过的记忆块和产品一样留在历史里，新开的对话则清空。

- **写回复**：每一轮由一个写回复的模型，根据对话和记忆块写出陪伴者的回复。两个配置在某一轮拿到的材料完全一样时共用一条回复，不重写。
- **评判**：第二个模型把一个配置的回复和基线的回复配成对，不告诉它哪条来自哪个配置，顺序随机（固定种子的硬币决定谁在 a、谁在 b）。对每条回复标三件事：`u` 是否恰当地用了一条有关或相关的记忆；`d` 是否扯进了不相干的东西；`w` 是否编造或说错。再说更喜欢哪一条，或者没有差别。评判看到的历史只有话，没有记忆块；摆在写回复一方面前的记忆按这一轮的标注分成有关的、同一个簇里给过的、不相干的给过的三份。
- **复评**：十分之一的对再以相反的顺序评一次，看偏好是否前后一致。
- **噪声底线**：基线再写一遍（`aa`），和第一遍配对评判，量同一份输入写两次会差多少。
- 写回复和评判的都是 Claude Haiku，各自照一份任务单、读输入文件、写一个 JSON；每份写回复的输入文件 24 条，每份评判的输入文件 20 对。脚本只负责切文件、合并和打分，不调用任何模型，没有 API 调用。

配置和对应的 `session_lab` 设定：

| 配置 | 内容 | 设定 |
|---|---|---|
| base | 现在的产品 | 无 |
| after | 回复之后再查一次，最多留 2 条 | `after:max=2` |
| recent | 新对话第一轮带上上一段对话里最强的 3 条 | `recent:size=3` |
| cap3 | 第二轮起每轮最多新交 3 条 | `noise:cap=3` |
| strict | 记忆块第一句用严格的说法 | 严格措辞 |
| combo | 前三项合在一起 | after、recent、cap3 |
| combo-strict | combo 加严格措辞 | |
| aa | 基线的第二遍写作 | |

先在 12 段会话（每个世界一段，95 轮）上跑了七个比较，作为试跑；之后对整个开发集跑了四个配置（after、recent、cap3、strict），combo、combo-strict 和 `aa` 只在试跑里有。

## 这把尺子可不可靠

| | 试跑（12 段，95 轮） | 整个开发集（36 段，284 轮） |
|---|---|---|
| 交换顺序复评的对数 | 48 | 63 |
| 偏好前后一致 | 34（70.8%） | 44（69.8%） |
| 偏好 a 的占比 | 49.0%（199 对 207） | 47.6%（279 对 307） |
| 偏好 a 对 b 的检验 p | 0.7283 | 0.2647 |

- **没有位置偏向**：两次的 a 占比都在一半上下，检验都不显著。
- **单次偏好很不稳**：顺序一换，三成的偏好变了。
- **同一份输入写两遍**（试跑里的 `aa`，95 对）：82.1% 的对被评为“不一样”，胜负是 42 比 36，另有 17 对持平；两遍之间标记不同的比例：`u` 19.3%，`d` 8.4%，`w` 7.4%。

由此得到的结论：单独一轮的偏好大半是噪声，同一份输入写两遍就会被评出“谁更好”。只有在很多轮上净差别很大，才看得出来。

## 试跑没有站住

试跑只用了 12 段会话，其中 strict 的结果很显眼：

| 配置（试跑，12 段，95 轮） | 评过 | 胜 | 负 | 持平 | p（轮） | 会话 偏向/反对/打平 | p（会话） |
|---|---|---|---|---|---|---|---|
| after | 51 | 23 | 22 | 6 | 1.0000 | 4/3/3 | 1.0000 |
| recent | 18 | 6 | 6 | 6 | 1.0000 | 3/4/4 | 1.0000 |
| cap3 | 60 | 29 | 23 | 8 | 0.4885 | 7/3/2 | 0.3438 |
| strict | 95 | 48 | 24 | 23 | 0.0063 | 11/0/1 | 0.0010 |
| combo | 81 | 29 | 33 | 19 | 0.7035 | 6/5/1 | 1.0000 |
| combo-strict | 95 | 43 | 35 | 17 | 0.4282 | 4/4/4 | 1.0000 |
| aa | 95 | 42 | 36 | 17 | 0.5716 | 6/3/3 | 0.5078 |

试跑里 strict 以 48 比 24 领先，11 段会话偏向它、没有一段反对，p 0.0010。整个开发集上，strict 是 113 胜 102 负。减去试跑的 12 段，其余 24 段会话上是 65 胜 78 负。另外两个配置也是这样：

| | 试跑的 12 段 | 其余 24 段 | 全部 36 段 |
|---|---|---|---|
| strict | 48 / 24 | 65 / 78 | 113 / 102 |
| after | 23 / 22 | 50 / 32 | 73 / 54 |
| cap3 | 29 / 23 | 34 / 58 | 63 / 81 |

（胜 / 负。其余 24 段的数字是全部 36 段减去试跑的 12 段。）

原因有两个：

1. **十几段会话对这把尺子太少。** 基线写两遍，同一份输入就能评出 42 比 36 的胜负，评判对同一对换顺序有三成不一致；十几段会话上出现的差距，不比这样的噪声大多少。
2. **每个输入文件由一次写回复的运行写成，一次运行的文风差异会成片地改变胜负。** 同一个文件里的回复一起偏向某种写法，所以一批轮是一起赢或一起输的，有效的样本比轮数少。符号检验假设每次试验独立，在这里不成立，列出的 p 值偏乐观。会话层面的检验更严，但同样没有去掉这个影响。

## 能说明什么，不能说明什么

- 在开发集上，没有哪个配置对评判后的回复显示出可靠的效果，好坏两个方向都没有。
- 多轮会话里，回复扯进不相干东西的情况很少：基线的 `d` 在 after、cap3、strict 各自评过的轮上是 5.2%、5.6%、6.3%（`recent` 只有 53 轮，1.9%）。[上一篇](2026-11-21-noise.md)在单句闲聊上用共享字句的办法量到的是三成左右。严格措辞在这里可以改善的余地因此很小。它还让恰当用到有关记忆的比例略降：`u` 从 47.2% 到 41.9%，升的有 21 轮，降的有 34 轮。
- 回复之后再查一次（after）是唯一方向一致为正的：73 胜 54 负，p 0.11（会话层面 17 对 8，p 0.1078）。这不够说它有效，而且它在 `u` 上是 -3.1 点。
- 对产品的结果：这几项设置都不设为默认，保持关闭并标为实验；严格措辞保留为一个可选的值。

## 没有量的、限制

- 没有在留出集上用这个工具跑过。
- 写回复和评判的是同一系列的小模型，换一个模型可能不同。
- 会话是照剧本写好的，主人的话不会跟着回复变化。
- 标注和会话是语言模型写成的，另由一轮独立的复查核对过。
- 相关性检查（回复前由模型挑选记忆）和带压缩的对话池不在这次评估里。
- 写回复的各次运行之间的批次差异没有去掉。
- 只用了一个聊天模型。

## 怎么重跑

流程六步，路径换成自己的：

```bash
python -B bench/chat/replies/plan.py --split bench/chat/dev --cache <向量缓存文件夹> --texts <回复文本文件> --work <工作目录>
python -B bench/chat/replies/prep.py write --work <工作目录>
# 写回复的模型按 TASK-REPLY.md 写出各份输出，放进工作目录
python -B bench/chat/replies/merge.py --work <工作目录>
python -B bench/chat/replies/prep.py judge --work <工作目录>
# 评判的模型按 TASK-JUDGE.md 写出各份输出，放进工作目录
python -B bench/chat/replies/merge.py --work <工作目录>
python -B bench/chat/replies/score.py --work <工作目录>
```

`plan.py` 默认跑全部配置；`--configs` 可以选其中几个（`base` 总是包含），`--sessions-per-world N` 每个世界只取 N 段会话。`merge.py` 列出缺的、多的、长度不合规的回复和读不懂的评判，这些要重做。
