# 多轮对话里的召回：会话题和三项测量

状态：只有测量。量的是 DSH 插件的两项原型（回复之后再查一次、对话池）和一项还没有做的东西（跨对话的近期池）；原型在一个没有合并的分支上，默认关。测量用的脚本是 `bench/chat/session_lab.py`（实验用，不是产品代码），题目是 [bench/chat](../../bench/chat/README.md) 里每个世界的 `sessions`。

## 为什么要有会话题

之前的题目每道只有一句话。[让模型帮着联想](2026-11-18-recall-with-a-model.md)量出“拿回复再查一次”能多找回记忆，但回复要等一轮结束才有，查到的记忆只能下一轮用；下一轮它还用得上吗，单句的题目答不了。同样答不了的还有：话题换了之后带着多少无关的记忆，第二天新开一个对话能不能接上前一天的事。

所以每个世界加了三段写好的对话，每段 6 到 9 轮，每个划分 36 段、280 多轮。每一轮标一种类型：靠联想开头（`open`）、点名开头（`named`）、不点名地接着聊（`continue`）、和任何记忆都无关的闲话（`idle`）、聊了别的之后不点名地绕回来（`return`）、隔了一两天新开对话又不点名地提起之前的事（`nextday`）。格式和写法见 bench/chat 的说明。题目是用语言模型按同一份出题说明分头独立写成的，再由另一轮独立的复查逐轮核对标注，开发集的题目由维护者抽查过。

## 怎么量的

按插件的做法一轮一轮回放：一轮给出的记忆块留在对话历史里，模型之后一直看得见，历史里已经有的记忆不再给。每一轮看两件事：

- **在眼前**：这一轮该用到的记忆（`direct`）是不是在模型看得见的地方，这一轮新给的，或者历史里还留着的。
- **这一轮新到了几条记忆，其中和这一轮有关的占多少**。

检索和产品一样（bge-m3，`broad` 档，`limit` 5，`linked` 开）。回复由一个小模型（Claude Haiku）按轮写成：它看得到这段对话到这一轮为止的内容和历史里的记忆，看不到后面的轮次，也看不到标注。设置只在开发集上选，写定之后在留出集上各跑一次。

## 现在的产品

| | 开发集 | 留出集 |
|---|---|---|
| `open` 在眼前 | 74.2 | 74.0 |
| `continue` 在眼前 | 71.6 | 71.6 |
| `return` 在眼前 | 77.8 | 72.2 |
| `nextday` 在眼前 | 36.1 | 47.2 |
| 全部有标注的轮次 | 70.6 | 70.6 |
| 闲话轮什么都没给 | 11.1 | 11.1 |
| 每轮新到的记忆 | 3.42 | 3.45 |
| 其中和这一轮有关的 | 22.3 | 23.9 |
| 一段对话结束时历史里的记忆 | 13.5 | 13.8 |

三件事：

- 接着聊和绕回来的轮次，十之七八靠的是**前几轮留在历史里的记忆**，不是这一轮查到的（开发集上 `continue` 这一轮新查到 `direct` 的只有 26.1%，`return` 只有 11.1%）。对话里的连续性现在是记忆块留在历史里撑着的。
- **隔天新开对话就接不上了**，历史没了，那句话又不点名。
- **每一轮新到的记忆只有不到四分之一和这一轮有关**，闲话轮十次有九次也带了东西，一段对话下来历史里攒了十三四条。之前在单句题上看到的“无关的多”，在多轮里是一轮一轮累积的。

## 回复之后再查一次

每轮结束时拿回复再查一次，历史里没有的记忆最多留 2 条，下一轮放在第二个块里。

| | 开发集 | 留出集 |
|---|---|---|
| `continue` 在眼前 | 71.6 → 84.1 | 71.6 → 78.4 |
| `return` 在眼前 | 77.8 → 88.9 | 72.2 → 80.6 |
| 全部 | 70.6 → 76.6 | 70.6 → 74.2 |
| 变好 / 变差的轮次 | 15 / 0 | 9 / 0 |
| 每轮多带 | 0.44 | 0.50 |
| 多带的里面和这一轮有关的 | 23.4 | 24.1 |

晚一轮到的记忆是用得上的：接着聊的时候，话题多半还是上一轮的。代价是多带的记忆里四条有三条和这一轮无关。最多留 1 条时收益减半，留 3 条和 2 条一样。

## 对话池：最初的规则不管用，改过之后才管用

原型里对话池的规则是：一条记忆给出时强度 1，每轮乘 0.8，主人的话提到它加 1，强度不低于 1 的才在历史被压缩之后带回来。模拟每 3 轮压缩一次历史：

| 留出集 | `return` 在眼前 | 全部 |
|---|---|---|
| 不压缩 | 72.2 | 70.6 |
| 每 3 轮压缩一次 | 44.4 | 64.7 |
| 压缩，加上改过规则的对话池 | 63.9 | 68.3 |

压缩一次，绕回来的轮次就掉一大截，说明这件事值得管。但按最初的规则，对话池在开发集上只救回 1 轮：只给过一次的记忆过一轮就掉到 1 以下，再也带不回来；而不点名的话里本来就没有记忆里的词，“提到就加强”很少触发。在开发集上比出来管用的改法是两处：带回来的门槛从 1 降到 0.3；一轮结束时，**回复里用到了哪条记忆，哪条就加 1**（和“提到”用同一条判断规则，只是看的是回复）。这样开发集上 `return` 从 38.9 回到 72.2，留出集从 44.4 回到 63.9。代价是每次压缩之后带回 3 条，其中和当时那一轮有关的很少（留出集 6.7%）。

## 近期池：新开对话时带上上一段对话里用过的

还没有做，这里只是估它值多少：新对话的第一轮，把上一段对话结束时强度最高的 3 条记忆带上（强度按上面改过的规则算，回复用到的加强）。

| | 开发集 | 留出集 |
|---|---|---|
| `nextday` 在眼前 | 36.1 → 72.2 | 47.2 → 80.6 |
| 变好 / 变差的轮次 | 13 / 0 | 14 / 0 |

只在每段新对话的第一轮多带 3 条，其中四分之一和那一轮有关。不看回复、只按给出的次数算强度时没有这个效果（开发集 36.1 到 41.7）：一段对话里给过的十几条记忆强度都差不多，挑不出哪几条是真聊过的。

另一种做法也量了：不是无条件带上，而是让上一段对话里的记忆在新一轮查询里更容易入选（相似度加上一个和强度成比例的小数再过分数线）。它在两个划分上都不如直接带 3 条（留出集 `nextday` 69.4 对 80.6），多带的还更多。

## 限制

- **对话、回复都是语言模型写的**，对话是事先写好的，不会因为模型的回复改变走向。没有在真实的聊天里验证过。
- “回复用到了哪条记忆”是按回复和记忆有没有一段相同的字来判断的。写回复的模型会把无关的记忆也用进回复（见上一篇记录），那样的记忆同样会被加强。
- 没有量回复的质量。所有做法都让模型眼前的记忆更多，其中大部分和当下无关；这对回复是好是坏，这里的数字说不了。
- 每 3 轮压缩一次历史是为了看清楚而设的，真实的宿主压缩得没有这么勤。
- 近期池要跨对话保存状态，谁的对话算“上一段”、存多久、存在哪，都还没有定。
- 一个嵌入模型，一个生成模型。
