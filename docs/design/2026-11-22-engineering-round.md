# 一轮工程整理：重构怎么核对，三处行为为什么改

状态：已实现。大部分是不改行为的重构，另有三处有意改了行为。搜索结果在整轮前后没有任何变化。

## 怎么保证“没有改坏”

测试全过不够：测试没有逐条钉住每个存储对每个问题返回什么。所以动手之前先录了一份行为记录，每一步之后重录一份，逐字节比较。

记录的内容：四种本机存储（`inmemory`、`sqlite`、`embedding`、`hybrid`）装进开发集的 160 条记忆，对 110 个问题各搜一次，记下每条命中的编号、分数、日期和文字；再记 `read`、`neighbours`，和一小段写入（一次写几条、回执、条数、删除）。`embedding` 和 `hybrid` 用测试里那个结果固定的假向量服务，不需要真的模型。另外把不需要向量服务的三张离线基准表原样存下。

同一份代码连录两次完全一致，说明记录本身是确定的。之后每一步（三项重构、三项行为改动、规范和类型的修正）的记录都和最初那份一样。

## 不改行为的部分

- **存储后端的公共部分只写一遍。** 五个后端里各自抄了一份的小工具（今天的日期、只读检查、回执和编号的写法、`put_many` 条目的解析等）搬进 `backends/base.py`；两个 SQLite 文件存储共用的建表、打开、计数、遍历放进 `backends/_sqlfile.py`。各后端自己的加锁方式不变：共用的函数拿一个“怎么读”的参数，由后端传自己的。各后端有哪些方法是别处用 `hasattr` 探测的，所以基类没有增加任何方法，逐个核对过前后一致。
- **`gateway/app.py` 按职责拆开。** 令牌（`tokens.py`）、请求体校验（`validate.py`）、启动检查（`policies.py`）各成一个文件，`Gateway` 留在原处。原来能从 `gateway.app` 取到的名字都还在。
- **插件的 `src/plugin.js` 拆开。** 接口窄的几块（路由、两个工具、自动记录、回复后再查）各成一个模块，用工厂函数接收它要用的东西；一轮对话从头到尾的主线留在原文件里，不为了拆而拆。
- **规范和类型检查进 CI。** Python 用 ruff 和 mypy，插件用 ESLint，只开和正确性有关的规则。插件的 `package.json` 不加依赖，ESLint 用 `npx` 按固定版本运行。

## 有意改了行为的三处

**一次写几条消息，全有或全无（`sqlite`、`inmemory`）。** 以前逐条写：第三条失败时前两条已经存下，网关回答失败、不给回执，调用方无从得知，重发就存两遍。现在先把每条都准备好，再在一个事务里写入；提交前看一眼调用方是否已经放弃（超时），放弃了就不写。仍然留着一个说不准的瞬间：网关刚判定超时，存储恰好提交成功。这时是全部写入，不是一部分，所以对外仍然说“可能写进去了，也可能没有”。`openviking` 是远端服务器上的会话，做不到这一点，文档里写明了。

**`hybrid` 同时问两路，并且说出哪一路没答上。** 以前一路问完再问另一路，各分一份时间；其中一路出错只是跳过，结果悄悄变成只有另一路的。现在各用一个线程同时问，每一路都拿到完整的时限。融合按子后端的顺序进行，所以结果和谁先答完无关。几点取舍：

- 线程由 `hybrid` 自己开，不借网关的线程池：后端拿不到那个池，而且“占着一个工作线程等另外两个工作线程”在小池子里会卡死。
- 网关给后端的取消句柄只有一个放套接字的位置，两路不能共用，所以每一路有自己的句柄，上层取消时一起取消。
- 一路失败或超时，记进 `child_failures`，并通过新的 `ctl.note()` 在这次请求的访问日志里留一个词 `child-failed`。后端本来碰不到请求的上下文，这是给它开的一个只能写“原因词”的口子。

**`embedding` 的搜索不等写入。** 以前一个连接一把锁，把全部向量读进内存也在这把锁里做，期间别的读写都得等。现在读走只读连接；读向量不占写入的锁，同时来的几次搜索只读一遍。

这里换掉了一样东西：以前靠 SQLite 的 `data_version` 发现“别的进程写过”，它是每个连接各算各的，而且把自己进程里另一个连接的提交也算作外来的。连接一多就没法用它精确判断，会在每次自己写入后白白重读全部向量。现在在库的 `info` 表里放一个写入计数，每次写入在同一个事务里加一，搜索前比一下计数。代价有两个，都写进了后端文档：库里多了一行（旧版本打开不受影响）；不经过这个后端、直接用 SQL 改库的写入不会加这个计数，运行中的进程要到重新打开库才看得到。

## 没做的

- `hybrid` 某一路失败的次数没有出现在健康检查里：健康检查每个存储只有“好”或“不好”，没有放计数的地方。现在只能从访问日志和 `child_failures` 看。
- 类型检查只要求检查器能看懂现有代码，没有给每个函数补标注。
- 测试和基准脚本不查行长。
