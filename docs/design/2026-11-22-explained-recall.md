# 解释召回：一条记忆为什么没有回来

状态：已实现。网关多了一个只读的请求 `POST /v1/explain`，DSH 插件的设置页面用它做了“试一下召回”。不用模型，不改存储格式，普通的召回没有变化。

## 问题

召回只返回交付的记忆。一条记忆没有回来，可能是没有被搜到，可能是分数低于分数线，可能是和最相关的一条差得太多、和前面一条重复、放不进字数预算，或者排在条数上限之后。这些原因以前哪里都没有记录：各个步骤去掉一条候选时不留痕迹，访问日志里只有几个原因词，不指向具体哪一条。

调分数线、换检索方式、判断“是没记住还是没想起来”，都得靠猜。

## 做法

**在引擎里记录，不改步骤。** 召回的步骤有两种动作：`prepare` 对整批候选做一遍（可以去掉、改分、添加），`admit` 对每条候选给一个决定。引擎本来就知道每一步前后各有哪些候选、每个决定出自哪一步，所以只在引擎里记：

- `prepare` 之后少了的候选，是这一步去掉的；多出来的，是这一步添加的。
- `admit` 里第一个不放行的步骤，就是做决定的那一步。
- 条数放满之后才轮到的、时限到了还没轮到的，各记一种结果。

候选按“来源加编号”认，因为一个步骤可以返回一个新的对象来表示同一条候选。内置的和自己写的步骤都不用改，也不用知道有这回事。

**回答。** 和召回一样的四个字段，再加步骤名的列表和每条候选的去向：进入时的分数、最后的分数、结果（交付、被去掉、放不下、超过上限、没轮到）、做决定的步骤、是哪一步添加的。候选的文字一律经过这个客户端的脱敏，最多 300 字；最多列 100 条。

**不算一次使用。** 解释召回不运行各步骤的 `finish()`。这个钩子按约定只做记账，遗忘曲线就是在这里给记忆记“用到一次”的。查看原因不应该让一条记忆变得更不容易被忘掉。

**没开解释时不多做事。** 普通召回不创建记录对象，路径上只多了几处“有没有在记录”的判断。测试对同一个问题分别开和不开解释，核对四个字段完全一样。

## 谁能用

解释召回比召回多给的，正是召回有意不交的东西：被分数线、去重、字数上限或某个步骤去掉的候选，连同分数和文字。所以：

- 默认关闭，配置里给客户端写 `explain = true` 才能用，别的客户端得到 403。
- 启动时核对这个客户端的[受众](2026-11-22-audience-levels.md)必须是 `owner`。内容会被别人看到的客户端配了它，网关拒绝启动。
- DSH 插件自己生成的配置给自己的客户端打开；它是主人的客户端，接口只在本机。

## 设置页面里的“试一下召回”

“检索”标签页的最后一节。输入一句话，列出网关为它看过的每条记忆：会给出的，和没给出的各自的原因。几点取舍：

- **用的是自动召回的那套查询处理。** 太短或只是一句应答的话，对话里插件不会为它召回，页面直接这样说明，不显示一个对话里不会出现的结果。
- **只显示网关的结果。** 网关回答之后插件还会做几件事（跳过这段对话里已经给过的记忆、每轮新记忆的条数上限、实验性的相关性检查），这些取决于具体的对话，试验台里没有对话，所以不模拟，页面上写明了这一点。
- **不碰对话的状态。** 试多少次，之后的对话都和没试过一样。测试用两个插件实例核对：一个先试三次再聊，一个直接聊，召回请求、记忆块和状态完全相同。
- **外部网关。** 版本旧或者没有打开 `explain` 时，页面提示不支持，不报错。

## 检查过的

- `tests/test_explain.py`：每种结果各一项；每条候选只出现一次，各结果的条数和 `more` 对得上；开和不开解释答案相同；不运行 `finish()`，遗忘曲线不记使用；文字的脱敏、截断和缺失；权限和启动检查。
- 把七处保证逐个改坏（受众检查、两处权限判断、`finish()`、脱敏、截断、`prepare` 的记录），测试每次都报错。
- 用插件的客户端代码连一个从源码启动的真网关：存几条记忆，同一句话的召回和解释交付的是同一批；没有打开 `explain` 的客户端得到“不支持”。

## 没做的

- 没有命令行的入口（`feiyu-memgate explain`）。只用网关不用 DSH 的人，现在要自己发 HTTP 请求或者用 Python 客户端的 `explain()`。
- 不显示分数线本身的数值，只说“低于分数线”。
- 没有在真的 DSH 里用过，页面是在预览里操作检查的。
