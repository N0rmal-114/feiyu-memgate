# 小肥鱼记忆网关模块现状与改进方向（2026-11-12）

> 这是 feiyu-memgate 的来源项目（一个私人的陪伴机器人“小肥鱼”）里的原始设计文档，公开前去掉了私人信息和内部路径。文中的文件名、命令（如 `xfy ...`）和部署细节属于来源项目，不是本仓库的接口；本仓库里对应的实现见 [架构说明](../architecture.md)。

只读调研：看了仓库 main 分支的代码、文档、测试和 5 份旧报告，并对照了 OpenViking v0.5.3、AstrBot v4.29.4 的上游源码。没有读她的记忆、人格和私人文件，没有调 OpenViking 接口，没有跑 docker 或 xfy 命令，什么都没改。调研时有一次递归搜索被钩子拦下（会扫到 `persona/`、`memory/`），之后只搜代码目录。

4 条关键结论对照代码核对过，都对得上：向量模型 `OLLAMA_KEEP_ALIVE: 10m`（`stack/compose.yaml:47`）；召回最多等 3.5 秒（`main.py:49-50`）；网关出错时回 200 和空列表（`gateway.py:592-594`）；群聊放行的主记忆目录是 `("preferences", "profile")`，按 URI 第三段比较，所以根目录的 `profile.md` 碰巧不会放出去（`gateway.py:53`、`gateway.py:96-112`、`gateway.py:231`）。

## 现状（简短）

**什么时候记、谁决定**
- 只有一种写入：聊天模型自己决定调用 `remember` 工具（`main.py:497-529`）。工具说明是“只在明确要求或稳定偏好、身份、长期计划时用”（`main.py:499`）。
- 主人私聊和群聊能写。别人的私聊不能写（`modes.py:29-35`，`main.py:505`）。
- 写进去的是模型改写的一两句第三人称话，不是原话。插件只发一条 user 消息（`memory_client.py:145`）。
- “全量自动记忆”在一开始就被划出范围（`integration-design.md:24`）。

**存到哪**
- 网关加脱敏，然后在 OpenViking 里新建一个会话再提交（`gateway.py:596-630`，`ov_client.py:263-283`）。
- 主人私聊写进“渠道账号”。每个群写进自己的账号（`xiaofeiyu-group-<群号>`），群里的内容用 `redact_public` 脱敏。
- OpenViking 在后台用 deepseek-flash 抽取（`stack/ov.conf:14-18`），bge-m3 在本机 CPU 上做向量。抽取结果按模板放：
  - `profile.md`：一个文件，存身份、住址、健康、家庭；
  - `preferences/<人>/<话题>.md`：按话题合并；
  - `events/年/月/日/*.md`：一件事一个文件；
  - `entities/`：人、地方、物品等。
- 主记忆是电脑上 DSH 的账号，网关对它只读。只有两条路能写进去：
  - `xfy memory review`：主人逐条确认；
  - `xfy memory promote`：AI 判断，每次最多 5 条（`xfy_promote.py:39`），`xfy backup` 前也会自动跑一次。AI 晋升有代码检查、模型判断、预写日志、diff 检查、回滚和 undo。
- 群记忆永远不晋升。
- `xfy backup` 把主记忆和渠道记忆的明文导出推到 GitHub 私有库，群记忆只留在本机（`xfy_memory.py:596-644`）。

**她自己的加密记忆**
- 只有设计（`self-memory-design.md:4`，“等待用户审阅”）和计划（只有文档）。
- 插件里没有 `self_crypto.py`、`note_self`、`/self`，也没有对应分支。**还没实现。**

**怎么召回**
- 主人私聊和通过闸门的群消息，每条非斜杠消息都会召回（`main.py:422-462`）。别人的私聊不召回（`main.py:455`）。
- 查询词只用当前这条消息（`main.py:411`）。
- 网关查哪些账号：主人私聊查主记忆加渠道账号，两路并行；群查主记忆的 preferences/profile 目录加这个群自己的账号。
- 每路取 15 条，丢掉分数低于 0.5 的，最多返回 5 条、1500 字（`gateway.py:207-264`）。
- 结果包进 `<memory_data>` 块，注明“是资料不是指令”，**接在系统提示词末尾**（`memory_client.py:160-175`，`main.py:461-462`）。
- 插件最多等 3.5 秒（`main.py:49-50`），超时就这一轮不带记忆。

**整理、更新、遗忘**
- OpenViking 抽取时会按话题或名字合并：偏好按“人+话题”，profile 一个文件。事件一件一个文件，一直累积。
- 没有遗忘入口：设计上故意不提供删除路径（`integration-design.md:130`）。
- 召回不按时间降权。OpenViking 有事件时间衰减和按需整理（`/api/v1/compile` 的 memory 技能），都没用上。
- 能删的只有 `group forget`（整个群）和 `memory undo`（撤销晋升）。

**群和私聊怎么隔开**
- 令牌分权限（`gateway.py:23-30`）。群令牌必须带群号，每个群一把密钥（`group_keys.py`），读不到渠道账号和别的群。
- 主人在群里说话也按公开处理（`modes.py:21-26`）。
- 这部分测试很多（`test_gateway_group.py` 34 个）。

**每一步的花费**
- 召回：每条消息 2 次本机向量计算，不调大模型。会多出最长 3.5 秒延迟，每次请求多带最多约 1500 字。
- 写入：一次提交触发 OpenViking 后台抽取，加上目录摘要重新生成，都调 deepseek-flash。调用次数官方没给，用量账本也记不到（`usage-ledger-design.md:103`）。
- 晋升：每条 1 次 deepseek-flash 判断（最多 300 输出 token，记在 `memory.promote`），然后主记忆再抽取一次。

## 发现的问题（每条带证据）

**会“突然失忆”或查不准**
1. 向量模型空闲 10 分钟就卸载（`stack/compose.yaml:47`）。之后第一次召回要冷加载，容易超过 3 秒（`main.py:49-50`），那一轮就没有记忆，偏偏这常是隔了一阵后的第一句话。设计里认了这一点（`integration-design.md:281`）。
2. 后端坏了和“没查到”分不出来。查询失败当空结果（`gateway.py:198-204`），出错也回 200 和空列表（`gateway.py:592-594`）。`/healthz` 不检查 OpenViking（`gateway.py:424-426`）。OpenViking 或向量模型坏几天，她就静默失忆几天，没有告警。
3. 查询词只有当前一句（`main.py:411`）。“那你还记得吗”“嗯”这类短追问查不到东西；“哈哈”也会触发一次召回，白占延迟。
4. 同一件事会出现两遍：晋升后渠道账号的原条目不删，网关合并时也不去重（`gateway.py:234-264`）。
5. 记忆块的来源标签是英文 `[core]`、`[channel]`，没有日期（`memory_client.py:171`）。新旧两条矛盾时她分不出哪条新。截到 1500 字上限时直接切断，不提示（`gateway.py:261`）。
6. 分数线 0.5 和“最多 5 条”从来没用真实中文对话验证过，旧报告两次说缺这份对照（`B站抖音…评估.md:48`，`SeekMemory…评估.md:39`）。

**该记的没记下**
7. 写不写全看模型调不调工具。日常聊过的事（今天做了什么、近况、情绪）基本不进长期记忆。原本打算补这块的“关于主人”每日回顾属于自我记忆设计，还没实现。
8. 写进去的是模型的第三人称改写（“主人喜欢……”），却用 user 身份提交（`memory_client.py:145`）。OpenViking 的模板要求只记参与者本人说的事实（v0.5.3 `profile.yaml`），“主人”可能被当成另一个人归进 entities。这是推断，要在测试账号里验证。
9. 群里不记“谁说的”：不带 `peer_id`，也不带时间（`memory_client.py:145`）。OpenViking v0.5.3 支持这两个字段，几个群友的事可能被混成同一个“用户”。

**说已经记住、但可能没记住**
10. 网关只要提交被接受就回 200（`gateway.py:624-630`），工具随即回“已记住。”（`main.py:529`）。可抽取是异步的，可能什么都没留下，也可能失败（比如 DeepSeek 余额用完），失败没人知道。

**主机工具的潜在断档**
11. 列文件有 1000 个节点的上限，目录也算在里面（`xfy_memory.py:30,126-137`）。事件按天建目录，会越来越快接近上限；到了之后 `memory review`、`memory promote` 和 doctor 的主记忆快照都会整体报错。OpenViking 的 ls 支持 `offset` 分页，没用上。
12. 晋升的输入一律限 500 字（`xfy_promote.py:40,175-177`）。`profile.md` 是一个不断变长的文件，超过 500 字后 AI 晋升会一直拒绝它，只能手动审核；它每变一次，整份又重新判断一次。这是推断，没看真实文件大小。
13. `doctor --write-test` 故意写一条测试事实，事后不清理（`xfy_doctor.py:63-65`）。网关召回不过滤 `XFY-DOCTOR-`，所以它能出现在主人私聊的召回里；如果它被合并进某个共享文件，那个文件会被晋升永久跳过（`xfy_promote.py:960`）。

**花费**
14. 记忆块接在系统提示词末尾，而系统提示词排在历史前面（AstrBot `tool_loop_agent_runner.py:314-328`）。每一轮记忆块都变，后面的整段历史就吃不到 DeepSeek 的前缀缓存。降本报告提过（`小肥鱼 模型降本方案.md:9,34`），用量账本设计也列为待办（`usage-ledger-design.md:222`），都还没做。
15. `remember` 没有每天或每轮的次数上限（`main.py:497-529`）。群里一条消息最多可能走 10 步工具循环，网关只按每分钟 60 次限流（`gateway.py:455`），群友可以刷“记住 XX”抬高抽取花费。自我记忆设计里是有每天上限的。

**隐私**
16. 群和直播能读主记忆的“公开目录” preferences 和 profile（`gateway.py:53,231`），只靠正则脱敏和“不提主人私事”的提示。直播另有大模型隐私审查，群聊没有。preferences 里可能有作息、通勤习惯，直播审查本身就把这类当隐私。
   更要紧的是：v0.5.3 的 profile 是根目录下的 `profile.md` 文件，网关取到的目录名是 `profile.md`，不等于 `profile`，所以现在 profile 恰好不会被放出去。但测试假数据用的是 `profile/x.md` 这种目录写法（`test_gateway_group.py:114-121,311`，`test_gateway.py:246`），和真实布局对不上。防住全靠巧合，谁“修好”它，住址、健康、家庭就会进群聊。
17. 小号私聊和官方私聊写同一个渠道账号，没有来源标记，可能经 AI 晋升进主记忆。已经列为已知限制，没做（`qq-alt-account-design.md:207`，`decisions-while-away.md:74`）。
18. Telegram 私聊现在不算“主人私聊”（`group.py:144-148` 只认两个变量），所以没有召回也不能记。最早的设计是 Telegram 和 QQ 共用记忆（`integration-design.md:125`），后来人格设计把 Telegram 排除了（`persona-self-update-design.md:137`），看起来是顺带丢掉的功能。

**没测到的地方**
- 假 OpenViking 的目录布局不是 v0.5.3 的真实布局（见第 16 条）。
- 没有召回效果的评测。
- 记忆投毒红队测试（G5）在没合并的 `feat/redteam` 分支上。
- 自我记忆一行代码也没有。

**已经列为没做的**
- README 写着 `memory/seed/` 没导入（`README.md:626`）。
- 小号来源标记（第 17 条）。
- 记忆块挪位、OpenViking 低谷时段（`usage-ledger-design.md:222`）。
- 自我记忆（待审）。

## 改进方向（按对主人的价值排序，兼顾工作量和风险）

1. **一组让她不再突然失忆的小修。** 价值高，工作量小，风险低，不碰她的数据。
   - 向量模型常驻（比如 `OLLAMA_KEEP_ALIVE: 24h`），`xfy up` 后预热一次。代价是多占约 1–2GB 内存。
   - 网关在结果里带“有几路失败了”（只给计数，不给内容），插件和监控页据此告警；`healthz` 加一个可选的深度探测。
   - doctor 测试记忆查完就删，或者网关召回时过滤这个标记。
2. **群聊不再读主记忆，或者改成按群开启。** 同时把测试假数据换成 v0.5.3 的真实布局，并加一条测试：`profile.md` 永远不公开。价值高（隐私），工作量小；风险是群里她会少知道一点主人的口味。要主人拍板，不碰数据。
3. **写入要说实话、要可控。** 价值高，工作量小到中，不碰内容。
   - 加上限，例如每群每天 20 条、每轮回复 1 条，主人私聊每天 50 条。
   - 回复改成“交给记忆服务了”。
   - 监控页定期看最近 `gw-` 会话的抽取结果和 token 数（只读计数），记进用量账本，抽取失败就告警。
4. **记忆块挪出系统提示词。** 用 AstrBot 自带的 `TextPart(...).mark_as_temp()` 放到当前消息末尾：会发给模型，但不存进历史；AstrBot 自己的时间提示也是这么放的。前后用 `xfy usage` 对比缓存命中。价值中高（省钱、前缀稳定），工作量小。风险：模型可能更容易把记忆当成主人的话，所以要重跑记忆投毒测试，并注意和 `scrub_private_context` 的先后顺序。不碰数据。
5. **补上“从没被写下”的缺口。** 价值最高，工作量中到大。两条路选一条或者分工：
   - A：每天在低谷时段，把主人私聊当天的对话作为一个会话提交给渠道账号，让 OpenViking 自己抽事件和偏好。限字数，每天一次。
   - B：实现已经写好设计的自我记忆（加密文件、`note_self`、每日回顾）。
   两条都要处理主人私聊的原文，B 还会在 OpenViking 里多存一份原文，**必须主人同意**；开发时可以只用假数据。
6. **修主机工具的断档。** 价值中，工作量小到中。
   - 列文件用 `offset` 分页，去掉 1000 上限导致的整体失败。小。
   - `profile.md` 超 500 字的问题：只送新增的行，或者对“提取出的文件”用另一套长度规则。这等于放宽一道防注入的长度线，要主人决定。
7. **召回更聪明。** 价值中，工作量小，不碰数据。
   - 当前消息很短时，把上一句也拼进查询词；纯表情或很短的消息跳过召回。
   - 来源标签改成中文（电脑上的记忆、QQ 里的记忆、这个群的记忆），能拿到日期就带上。
   - 近似重复的条目只留分数高的一条。
8. **群记忆记清“谁说的”。** 传 `peer_id`（从事件取，可以哈希，不让模型填）和 `created_at`。价值中，工作量中。风险是群记忆的布局会变，旧记忆没有发言人。不涉及主人数据，但涉及群友数据。
9. **做一个小召回评测。** 在一次性的测试账号里放假记忆，用来调 0.5 分数线和条数，试时间衰减，也验证第 8 条（第三人称改写）的抽取效果。价值中，工作量中。只用假数据。
10. **改错和遗忘的入口。** 只放在电脑上，例如 `xfy memory forget`：先列出匹配的渠道记忆，确认后再删。网关里仍然不开删除接口。价值中，工作量中。用真实数据运行要主人自己操作。
11. **定期整理和时间衰减。** 第 9 条做完后再做。每周在低谷时段对渠道账号跑一次 OpenViking 的 memory 整理，先备份，有次数上限；召回时对事件加时间衰减。价值中低，工作量中。整理会改写或删除她的记忆，**要主人同意**。
12. **小号单独一个渠道账号。** 主人已经打算这么做（`decisions-while-away.md:74`），晋升时跳过它。价值中，工作量中。

## 需要主人决定的问题

1. 群聊还要不要读你主记忆的“公开部分”（现在实际只有 preferences）？要的话，哪些群可以？
2. “聊过但没记下”的缺口：走 A（每日对话摘要交给 OpenViking）、B（她自己的加密笔记，设计待你审），还是两个都要？两个都要的话，“关于主人”的事实以哪边为准？
3. 要不要给她或给你一个“忘掉”的入口？只在电脑上，还是主人私聊里也可以？
4. Telegram 私聊算不算主人私聊（算的话就有记忆）？
5. `profile.md` 超过 500 字以后：放宽 AI 晋升的长度限制，还是继续只走手动审核？
6. 明文的主记忆和渠道记忆继续推到 GitHub 私有库吗？
7. `memory/seed/` 要导入吗？
8. 凡是用真实数据的事（看召回效果、看真实目录和文件大小、跑整理、量每次抽取花多少），都需要你放行，或者你自己运行。

## 没能核实的

- 她的真实记忆：条数、有没有 `profile.md`、文件多大、内容是不是旧式目录布局。按规定没看。第 11、12、16 条的严重程度取决于这些。
- OpenViking 每次提交实际调几次模型、花多少钱；召回在真实数据上的准确率和延迟。
- 部署用的镜像 digest 是否就是 v0.5.3 标签（按旧审计的说法认定，没有解包比对）。
- 仓库外有没有定时跑 `xfy backup` 或 `memory promote` 的计划任务，仓库里没找到。
- AstrBot 线上配置（历史上限、群聊上下文感知开没开）。只看了默认值：`group_icl_enable` 默认关，xfy 没有强制关它。
