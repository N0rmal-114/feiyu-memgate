# dsh-feiyu-memgate 更新记录

这是 DSH 插件 `dsh-feiyu-memgate` 的版本记录。网关本身的改动在仓库根目录的 [CHANGELOG.md](https://github.com/N0rmal-114/feiyu-memgate/blob/main/CHANGELOG.md)；附加插件 `dsh-feiyu-memgate-embed` 目前只有 0.1.0 一个版本。

每个版本下，“默认行为的变化”列出升级后不用改设置就会不一样的地方，每一项都写了怎么改回去。

## 未发布

三项实验功能，默认关闭，只做过离线测量。设计说明和测量见 [docs/design/2026-11-18-recall-with-a-model.md](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-recall-with-a-model.md)。实验设置都关着（默认）时，对话里没有任何变化（设置页面多了更新日志标签页，见下）：不注册新的监听，不保存对话状态，不写文件，不多做查询，记忆块和失败说明和 0.3.2 一样。

### 新增

- 设置页面多了一个“更新日志”标签页：当前版本，以及每个已发布版本改了什么，新的在前，最新的一条展开，其余折叠。内容读自插件包里的 CHANGELOG.md（中文），通过只有所有者能访问的路由 `GET /feiyu-memgate/changelog` 提供，不联网；页面只画标题、列表、段落、代码、粗体和 https 链接，文件里的 HTML 不会进页面。`/memgate changelog` 用纯文本显示最新发布的那一条。
- 实验设置 `advanced.afterthought`（默认关）：每次回复之后，在后台拿这条回复当查询再查一次记忆；历史里没有任何块给过的记忆，最多留 `advanced.afterthoughtMax` 条（默认 2，1 到 5），下一轮放在记忆块之后的第二个块里。回复要等一轮结束才知道，所以这些记忆晚一轮才到模型那里。
- 实验设置 `advanced.conversationPool`（默认关）：在内存里记住这个对话给过哪些记忆；宿主压缩了历史、记忆块不在了，把仍在谈论中的几条（最多 `advanced.poolSize` 条，默认 3，1 到 5）再给一次。强度从 1 起，每轮乘 0.8，你的新消息提到它或助手的回复用到它加 1（按相同的字句判断），不低于 0.3 才会带回，所以只给过一次的记忆约五轮内算数。不写磁盘。只开 `advanced.conversationPool` 时，每轮结束也会读一次回复。
- 实验设置 `advanced.recentPool`（默认关）：新的对话开始时，在它的第一轮把上一个对话还在用的记忆（强度不低于 0.5，最强的 `advanced.recentSize` 条，默认 3，1 到 5）在第二个块里给一次。为此，每一轮结束时把强度不低于 0.5 的记忆（最多 12 条）存到数据文件夹里的 `recent-pool.json`（文字、日期、来源标签、强度、对话编号和保存时间；原子替换，内容不进日志）。`advanced.recentDays`（默认 7，1 到 30）以前存的文件不再带。关掉这项会删除这个文件；插件停止时文件留着。记录强度的那部分（提到、用到、衰减）在 `advanced.conversationPool` 或 `advanced.recentPool` 任一打开时都运行，压缩之后带回记忆仍然只由 `advanced.conversationPool` 决定。
- 这些设置在设置页面、`/memgate` 和 profile 文件里都能改，每一轮重新读取，不重启网关。三项功能都需要 `modules.autoRecall`。
- 设置 `advanced.blockTone`（默认 `normal`，和以前完全一样）：设为 `strict` 时，主记忆块的第一句改成说明这些记忆大多与当前消息无关、明显有关才用、拿不准就不要提。第二个块和 `memgate_search` 不变。`strict` 也会让模型少用有关的记忆。
- 设置 `advanced.maxNewPerTurn`（默认 0，不限）：设为 1 到 5 时，一个对话从第二轮起，主记忆块最多带这么多条新的记忆，取网关顺序里去掉已给过的之后最前面的几条；“还有几条”那一行加上被去掉的条数。第一轮和第二个块不受限制。
- 这两项设置每一轮重新读取，设置页面、`/memgate` 和 profile 文件里都能改。
- 实验设置 `advanced.relevanceCheck`（默认关）：这一轮的记忆块给出之前，让一个模型看一遍你的消息和候选记忆，挑出“一个了解你的朋友会想到”的几条，只有这几条进记忆块；一条都没留下就没有记忆块，也没有说明。用的模型是对话本身的，或者 `advanced.relevanceProvider` 和 `advanced.relevanceModel` 一起指定的另一个；`advanced.relevanceTimeoutMs`（默认 3000，500 到 10000）是时限。失败、超时、回答没法用、宿主没有模型服务时，这一轮照没打开那样给出，日志只记类别。第二个块和 `memgate_search` 不检查。被去掉的记忆不记作已给过。`advanced.maxNewPerTurn` 在挑选之后才用。
- 设置页面的状态里，挑选打开时多一行“回复前的挑选”，显示调用次数、留下和去掉的条数和按类别的跳过次数。
- 这项功能每有候选记忆的一轮，回复之前就多一次模型调用：更慢，按该模型计费；你的消息和候选记忆会发给该模型的提供方。
- 设置页面的源码拆成了 `client/src` 下的一组小模块，由 `npm run build-client` 拼成宿主加载的那一个脚本 `client/client.js`；设置表里每个字段多了三个只供页面使用的说明（`needs`、`unit`、`experimental`）。页面的重新设计见下一条。
- 设置页面重新设计了。最上面是当前状态的摘要（正常工作、正在准备、在休息或需要处理），带几条要点；下面是五个标签页：概览、功能、检索、高级和更新日志（第六个“反馈”见下）。“高级”里的设置分成几个可折叠的组，默认合上，组名旁边标出改过几项。只在另一项设置取合适的值时才有意义的设置，会跟着那一项的开关出现。页面底部的一个条一次保存或放弃所有暂存的修改。浅色和深色跟随宿主的主题。设置的内容、保存方式（所有修改一次写入）和各项设置本身没有变化。
- 状态摘要旁边有项目吉祥物的小图，随状态换四种样子（正常、准备中、休息、出问题）。四张图在包里的 `client/art`（WebP，每张约 25 KB），通过只有所有者能访问的路由 `GET /feiyu-memgate/art/<文件名>` 提供，不联网；图加载不出来时页面照常可用，只是没有图。
- 设置页面不再使用宿主的界面组件，开关、输入框、按钮等都是页面自己的，所以在不同的宿主版本上外观一致；页面向宿主只要 `react`。
- 设置页面多了一个“反馈”标签页，用来给项目提建议或报告问题。选一下是关于什么的（建议、问题、其他），写几句话，点“提交”。页面用一次不带 cookie 和凭据的 POST 把你写的内容发给项目的反馈接收服务（地址写在 `client/src/constants.cjs` 的 `FEEDBACK_ENDPOINT`），由它存成一个私有仓库里的 issue，只有维护者能看到，不会公开，也不需要任何账号。这是设置页面唯一一次访问本机之外的地址，只在你点“提交”时发生。“附上运行环境”打开时（默认打开），一并带上插件和向量插件的版本、网关和检索的状态、Python 和 Node 的版本、操作系统类型和界面语言；附上的每一行都列在开关下面，不含记忆内容、条数、路径、地址和密钥，值里出现版本号和状态名以外的字符时写成问号。页脚的“反馈问题”链接改成了“提意见”，点了转到这个标签页。
- 提交失败时，页面写明原因（接收方拒绝、太频繁、连不上、超时），写的内容留在输入框里，并给出两条备用的路：“去 GitHub 提交”在浏览器里打开 GitHub 的新建 issue 页面，标题和正文已经填好，你在那里点提交之后才会发出（issue 是公开的，需要 GitHub 账号）；“复制全文”把同样的内容复制到剪贴板。内容太长、放不进链接时，链接里只带开头并标明截断，点链接的同时会复制全文。
- “反馈”标签页的标题旁边有一张小图：吉祥物指着在地上睡觉的小黑猫，对话气泡里写着“快更新！”（气泡是页面上的文字，英文界面显示英文）。图是包里的 `client/art/mascot-nag.webp`（约 35 KB），和状态摘要的四张图一样通过只有所有者能访问的路由提供；加载不出来时页面照常可用，只是没有图。
- 接收服务的代码在仓库的 `plugins/dsh-feiyu-memgate/feedback-worker/`（一个 Cloudflare Worker，不随插件包发布）：只接受一种固定形状的小 JSON，逐项检查；有按发送方和按总量的每分钟限流；回答里不重复收到的内容，不保存发送方的地址。部署步骤见该文件夹的 README。
- `/memgate feedback`：给出同一个新建 issue 页面的链接，里面只填好上面那几行运行环境。命令不发送任何内容，也不接收文字。
- 状态接口 `GET /feiyu-memgate/status` 多了 `runtime`（`platform`、`arch`、`node`），供上面两处使用。
- 开发用：`node scripts/preview-client.mjs --react <带有 react 和 react-dom 18 的 node_modules 文件夹>` 在浏览器里预览设置页面，不需要 DSH；状态和模型清单是编造的几种情形，说明见 `client/README.md`。

### 没有验证的

记忆块的说法和条数上限只做过离线测量（[设计说明](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-21-noise.md)）：照常说法下，回复闲聊时 30% 到 37% 用上了无关记忆，回复无关的寒暄时 50% 到 63%；strict 说法下降到 6.5% 到 12.7% 和 2.6% 到 4.8%，而用上有关记忆的回复从 84% 到 90% 降到 70% 到 77%。每轮最多三条新记忆使每轮到达的无关记忆少了 13%，248 轮里有 2 轮少了需要的记忆；最多两条则有 21 轮。数据是语言模型写的闲聊和记忆、一个小模型的回复和判断，“用到”按相同字句判断；量过的 strict 说法是对写回复的模型的指示，插件里的那句话是改写，没有单独量过；没有在真实的聊天里验证。

回复前的挑选只做过离线测量（[设计说明](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-21-noise.md)，括号里是开发用的那一批）：交出去的记忆里，有关的占比从 36.2% 到 77.6%（35.3% 到 79.9%）；有关的记忆留下 91.0%（87.6%），无关的留下 14.9%（12.0%）；直接相关的那条在 89 例里留住 87 例（76 例里 75 例）；和任何记忆都无关的寒暄里，一条都没留的占 66.7%（83.3%），只靠查询自己安静的是 20.8%（12.5%）。一个小模型分批挑的；闲聊和记忆是语言模型写的；多一次调用的延迟和费用没有量；没有在真实的聊天里验证。对宿主模型接口（`llm` 服务、`prepareCall` 和流）的用法是照宿主源码和已安装的版本写的，没有在真实宿主上跑过。

在留出的闲聊上，拿回复再查一次，直接相关的那条记忆交出去的比例是 72.2%，原来是 61.8%；和它相连的记忆是 60.7%，原来是 44.1%；最多多加两条。这是用语言模型写的闲聊和回复、一个嵌入模型离线量出来的。没有在真实的聊天里验证过，没有测对模型回复的影响，没有在真实宿主上看过压缩之后对话池的表现。对话池另外量过，同样是离线的：用语言模型写的多轮对话脚本，回复由一个小模型写，每隔三轮模拟一次压缩（[docs/design/2026-11-18-sessions.md](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-sessions.md)）；在回到前面话题的那些轮次里，需要的记忆摆在模型面前的比例，留出的对话上是 63.9%，原来是 44.4%（开发用的对话上是 72.2%，原来是 38.9%；不压缩时，留出的对话是 72.2%，开发用的是 77.8%）。“用到”按相同的字句判断，模型在不该出现的地方硬用上的记忆也会被加强。

近期池另外量过，同样是离线的（对话和回复都是语言模型写的，一个嵌入模型，[docs/design/2026-11-18-sessions.md](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-sessions.md)）：在回到前面对话、却不点名那条记忆的那些轮次里，需要的记忆摆在模型面前的比例，留出的对话上从 47.2% 到 80.6%（开发用的对话上从 36.1% 到 72.2%），好了 14 轮，没有变差的；带上的记忆里约四分之一和第一轮有关。只按给出的次数算强度时是 36.1% 到 41.7%，所以这项功能靠的是强度反映了用到的情况。文件里是记忆的文字，是记忆库之外插件唯一写下记忆文字的地方；记忆库里后来被遗忘或被取代的记忆，在文件被覆盖或过期之前仍可能被带进新对话；“上一个对话”是最后一个别的、用这个插件结束过一轮的对话，这个宿主上所有的对话都算同一个人的。没有在真实的聊天里验证过。第二个块里可能有和新消息无关的记忆，它也让上下文变长。数字是向量检索的；用 `keyword` 检索时，回复是一整句话，再查一次基本查不到东西。

## 0.3.2

日期：2026-11-18。自带网关为提交 `7de07c6`。

闲聊时顺带想起相连的记忆，设计说明和测量见 [docs/design/2026-11-18-linked-recall.md](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-linked-recall.md)。

### 默认行为的变化

- **用向量检索时，顺带想起相连的记忆。** 召回之后，网关顺着交出去的前两条记忆，找和它们最相似的记忆，把相似度够高（0.60）的最多再加两条，总数不超过 `advanced.recallLimit`。用 `endpoint` 或 `local` 检索（开不开 `retrieval.hybrid` 都一样）时生效；`keyword` 下没有变化。每顺着一条记忆，要把已存的向量多扫一遍。用 bge-m3 在 48 句留出的闲聊上通过真实的网关量得：和一句话所触及的记忆相连的记忆，混合检索下交出去的比例从 26.4% 到 41.7%，单用向量检索从 29.2% 到 42.7%；每句话交出的条数，混合检索从 2.9 到 3.7，向量检索从 3.7 到 4.3；没有相关记忆的轮次和以前一样安静（混合检索 43.8%，向量检索 31.2%），追问没有变差。一道题约两个点。改回去：`advanced.linkedRecall` 设为关。

### 新增

- 新设置 `advanced.linkedRecall`（默认开），在设置页面、`/memgate` 和 profile 文件里都能改。改动它会重启自带的网关。

### 修好的

- 自带的网关里，命令行在写不出中文的控制台上不再以错误结束（这项修复在 0.3.1 发布之后才打包进来）。插件启动网关时已经指定了编码，所以它不改变插件的行为。

### 没有验证的

上面的数字只来自一个模型（bge-m3）和一小组编出来的例子；别的模型沿用同一个相似度门槛，没有量过。没有在和真实模型的聊天里验证过。

## 0.3.1

日期：2026-11-17。自带网关为提交 `9b00619`。

聊天体验的第一轮改进，设计说明见 [docs/design/2026-11-17-chat-experience.md](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-17-chat-experience.md)。

### 默认行为的变化

- **本会话里给过的记忆不再重复。** 对话历史里还留着的记忆块已经出现过的记忆，这一轮不再放一次；全部都给过时不加记忆块。以前只和上一个记忆块整块比较。改回去：`advanced.skipRepeats` 设为关。
- **记忆块写明今天的日期，每条记忆带上多久以前。** 例如“（记忆，2026-10-27，3 周前）”。`memgate_search` 返回的块也一样。改回去：`advanced.showAge` 设为关。
- **召回失败时告诉模型。** 查询超时、出错，存储失败或繁忙而没有结果，或者自带网关还在启动时，在用户消息之后加一行说明；只在连续失败的第一轮加。改回去：`advanced.failureNote` 设为关。
- **自动记录跳过无关紧要的消息。** 打开 `modules.autoCapture` 时，聊天命令、只有语气词的消息和不足 4 个字的消息不保存。长度门槛用 `advanced.captureMinChars` 调，设为 0 就不看长度。

### 新增

- 保存的记忆带上本机时区的当前时间，记忆的日期是用户所在地的日期（以前是 UTC 日期，早上记的事可能算成前一天）。
- 系统提示词里的说明有中文和英文两个版本，跟随语言设置；说明和 `memgate_remember` 的描述补充了三点要求：写成单独看也能懂的一句话，时间写成日期，事情变了要说明取代了什么。
- 四项新设置：`advanced.skipRepeats`、`advanced.showAge`、`advanced.failureNote`、`advanced.captureMinChars`。

### 没有验证的

这些改动由单元测试和模拟宿主的测试覆盖，没有在和真实模型的聊天里验证过；“今天的日期和多久以前”对回答质量的影响没有测量。

## 0.3.0

日期：2026-11-17。自带网关为提交 `403931f`（没有变）。

### 新增

- 可选的混合检索 `retrieval.hybrid`（默认关闭）：在向量检索（`endpoint`、`local`，以及 `auto` 选到 `local` 时）下同时做关键词检索并合并结果。向量存储文件不变，旁边多一个关键词索引文件；每次网关启动之前，插件先让索引和向量文件一致，所以开或关都不会丢记忆。

没有改任何默认值。

## 0.1.0

日期：2026-11-15。

第一个版本：自带并自动启动网关，每轮自动召回，`memgate_remember` 和 `memgate_search` 两个工具，`/memgate` 聊天命令，设置页面，关键词、向量接口和本地模型三种检索方式。
