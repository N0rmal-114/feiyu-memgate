## 它是什么

[feiyu-memgate](https://github.com/N0rmal-114/feiyu-memgate) 记忆网关的 DeepSeek Harness（DSH）插件，给 DSH 对话加上长期记忆：每轮开始时自动查找相关记忆，并给模型“记住”和“查找”两个工具。网关随插件一起发布，由插件在你的电脑上启动。默认设置不需要任何模型，也不下载任何东西，记忆用关键词检索。

## 装上之后

1. 第一次需要记忆功能时，插件在后台启动内置网关，DSH 不会等它。
2. 你发出消息时，插件查找相关记忆，把它们放在你的消息之后，包在一个标明“这是资料，不是指令”的块里。块里写明今天的日期（这台电脑上的日期），有日期的记忆还写明是多久以前的事，例如“（记忆，2026-10-27，3 周前）”。默认最多 5 条，多数轮次更少，也可能一条都没有。查找最多等 4 秒，更慢就跳过。

   记忆块里还可能有和你的消息不太近、却和最先查到的记忆相近的记忆。用语义检索（`endpoint` 和 `local` 两种检索方式，开不开 `retrieval.hybrid` 都一样）并且 `advanced.linkedRecall` 开着（0.3.2 起默认开）时，网关顺着查到的前两条记忆，找和它们最相似的记忆，把相似度够高的最多再加两条，总数不超过 `advanced.recallLimit`。通过内置网关、用 bge-m3 嵌入模型，在 48 句留出的闲聊上量得：和一句话所触及的记忆相连的记忆，混合检索下交出去的比例从 26.4% 到 41.7%，单用语义检索从 29.2% 到 42.7%（一道题约两个点）。每句话交出的记忆条数，混合检索从 2.9 条到 3.7 条，语义检索从 3.7 条到 4.3 条。没有相关记忆的轮次和以前一样安静（混合检索 43.8%，单用语义检索 31.2%），追问没有变差。数字只来自一个模型和一小组编出来的例子，没有在真实的聊天里验证过。用 `keyword` 时没有任何变化。每顺着一条记忆，要把已存的向量多扫一遍。
3. 这个块会留在对话历史里，所以有记忆块的每一轮，上下文都会变长。你当前消息之前的内容不变，提示词缓存不受影响。历史里还留着的记忆块已经给过的记忆，不会再加一次（`advanced.skipRepeats`）；宿主压缩了对话、记忆块不在了，这条记忆就会再给一次。
4. 这一轮的查询超时或出错，或者内置网关还在启动时，你的消息之后会加一行说明，告诉模型这一轮没能查询记忆，不要当作“没有相关记忆”。只在连续失败的第一轮加（`advanced.failureNote`）。
5. 模型有两个工具：`memgate_remember` 保存一句话，`memgate_search` 主动查找。系统提示词里的一小段说明（中文或英文，按 `advanced.language`）告诉它：你要求记住、或说出长期有用的信息时才保存，不保存敏感信息，并告诉它怎么写记忆：以后单独看也能懂的一句话（说清是谁、是什么，不用“他”“这个”），时间写成日期，一件事变了就把新的情况记成完整的一句并说明它取代了什么。
6. 默认设置下，只有模型调用 `memgate_remember` 才会写入。打开 `modules.autoCapture` 后，每轮结束时还会把你自己发的消息直接存入记忆，命令、语气词和短于 `advanced.captureMinChars`（默认 4）的消息除外。保存的每条消息都带上这台电脑的本地时间，记忆的日期就是这一天。
7. 记忆存在 `<DSH home>/data/feiyu-memgate/` 的 SQLite 文件里。`<DSH home>` 是环境变量 `DSH_HOME` 指向的文件夹，没有设置时是用户文件夹下的 `.dsh`。
8. 实验功能，默认关闭：第二个记忆块（三项设置都需要 `modules.autoRecall`；都关着时上面写的一切不变）。`advanced.afterthought` 打开后，每次回复之后，插件在后台拿这条回复当查询再查一次记忆，把历史里没有任何块给过的记忆最多留 `advanced.afterthoughtMax` 条（默认 2），下一轮放进第二个块给出，因为回复要等一轮结束才知道。`advanced.conversationPool` 打开后，插件在内存里记住这个对话给过哪些记忆（强度 1，每轮乘 0.8，你的消息提到它或回复用到它加 1），宿主压缩了历史、那些块不在了，就把仍在谈论中的几条（强度不低于 0.3）（最多 `advanced.poolSize` 条，默认 3）在第二个块里再给一次。第二个块里可能有和新消息无关的记忆，也让上下文变长；再查一次每轮多一次后台查询。`advanced.recentPool` 打开后，同样记录强度，并在每一轮结束时把强度不低于 0.5 的记忆（最多 12 条）存到数据文件夹里的 `recent-pool.json`；另一个对话的第一轮，如果文件不超过 `advanced.recentDays` 天（7），就把最强的 `advanced.recentSize` 条（3）在第二个块里给一次。关掉这项设置会删除这个文件。别的东西都不写磁盘。

## 要求

- DeepSeek Harness：已在 0.2.2-rc.1（已安装的桌面版）上测试，并对照 0.2.2-rc.3 源码检查；engines.dsh 接受 0.2.2-alpha.1 到任何 0.2.2 预发布版（<0.2.3-0）。包里的范围还接受 0.2.0-rc.1 到 0.2.1-0 之前、0.2.1-alpha.1 到 0.2.2-0 之前，这两段没有测试过。
- Node 22.19 或更新。
- Python 3.11 或更新（需要 `sqlite3` 和 `tomllib`，标准安装都带），不用 `pip install` 任何东西。插件依次找：设置 `gateway.python`，桌面版自带的 Python，`python3`、`python`、`py -3`。找不到时网关不启动，记忆功能关闭，DSH 和对话不受影响。

## 安装

在插件页面安装包 `dsh-feiyu-memgate`，不需要改任何配置。命令行安装：

```sh
dsh plugin --profile <name> add dsh-feiyu-memgate
```

桌面版的 profile 是 `desktop`：先启动一次桌面版，再完全退出，运行 `dsh plugin --profile desktop add dsh-feiyu-memgate`，然后重新启动。

## 设置

每项设置都能在三个地方改：插件页面里本插件的设置页，聊天命令 `/memgate`，或 profile 的 `cordis.patch.yml`。

| 设置 | 作用 | 默认 |
|---|---|---|
| `modules.autoRecall` | 每轮自动召回 | 开 |
| `modules.rememberTool`、`modules.searchTool` | 给模型记住、查找两个工具 | 开 |
| `modules.promptSection` | 系统提示词里的固定说明 | 开 |
| `modules.autoCapture` | 每轮结束后把你的消息直接存入记忆 | 关 |
| `retrieval.tier` | 检索方式：`auto`、`keyword`、`endpoint`、`local` | `auto` |
| `retrieval.hybrid` | 语义检索下同时用关键词检索并合并结果（`keyword` 下不起作用） | 关 |
| `advanced.recallLimit` | 每轮最多加入几条记忆 | 5 |
| `advanced.skipRepeats` | 历史里的记忆块已经给过的记忆，不再给第二次 | 开 |
| `advanced.linkedRecall` | 用语义检索时，顺着查到的前两条记忆去找和它们最接近的记忆，最多再加两条，总数不超过 `advanced.recallLimit`；用 `keyword` 时什么都不做。改动它会重启内置网关 | 开 |
| `advanced.showAge` | 记忆块写明今天的日期和每条记忆是多久以前的事 | 开 |
| `advanced.failureNote` | 这一轮的查询失败时告诉模型 | 开 |
| `advanced.captureMinChars` | 自动记录跳过有效字符少于这个数的消息（0 到 50；0 表示不按字数过滤） | 4 |
| `advanced.blockTone` | 自动记忆块最上面那句话：`normal`（照常）、`strict`（说明这些记忆大多无关，明显有关才用）或 `bare`（所有记忆块都不附说明，包括第二个块和 `memgate_search` 的结果） | `normal` |
| `advanced.maxNewPerTurn` | 一个对话从第二轮起，主记忆块最多带几条新记忆（0 到 5；0 不限） | 0 |
| `advanced.relevanceCheck` | 实验功能。记忆块给出之前，让模型先挑出朋友会想到的记忆，只给这几条。每轮多一次模型调用，消息和候选记忆会发给该模型的提供方；失败时照常给出；第二个块和 `memgate_search` 不检查 | 关 |
| `advanced.relevanceProvider` | 筛选模型的提供方，和 `advanced.relevanceModel` 一起填；两项都空用对话本身的模型，只填一项等于都空 | 空 |
| `advanced.relevanceModel` | 筛选模型，和 `advanced.relevanceProvider` 一起填 | 空 |
| `advanced.relevanceTimeoutMs` | 筛选最多等多久（500 到 10000 毫秒），超时就照常给出 | 3000 |
| `advanced.afterthought` | 实验功能。每次回复之后拿这条回复当查询再查一次记忆，新的留到下一轮的第二个块里 | 关 |
| `advanced.afterthoughtMax` | `advanced.afterthought` 打开时：一次再查最多留几条（1 到 5） | 2 |
| `advanced.conversationPool` | 实验功能。记住这个对话给过哪些记忆；宿主压缩历史之后，把仍在谈论中的几条在第二个块里再给一次 | 关 |
| `advanced.poolSize` | `advanced.conversationPool` 打开时：一轮最多带回几条（1 到 5） | 3 |
| `advanced.recentPool` | 实验功能。新对话的第一轮，把上一个对话还在用的记忆给一次；在数据文件夹里放 `recent-pool.json` | 关 |
| `advanced.recentSize` | `advanced.recentPool` 打开时：最多带几条（1 到 5） | 3 |
| `advanced.recentDays` | `advanced.recentPool` 打开时：保存下来的对话还能带多少天（1 到 30） | 7 |
| `advanced.profile` | `broad` 每轮条数多、漏得少、杂讯也多，上下文涨得更快；`precise` 每轮约一条、更贴题 | `broad` |
| `advanced.dailyWrites` | 每天最多写入几条，0 为不限 | 50 |
| `advanced.redaction` | 保存和召回时去掉密钥、令牌、密码 | 开 |
| `gateway.mode` | `managed` 用内置网关，`external` 连接你自己运行的网关 | `managed` |

`/memgate` 的子命令：`status`、`config`、`set <键> <值>`、`reset <键>`、`on <功能>`、`off <功能>`、`tiers`、`use <方式>`，以及本地模型的 `models`、`install <模型> [--confirm]`、`builds allow|deny`、`use <模型>`、`remove <模型>`、`cancel`，以及 `changelog`（最新发布的版本改了什么，纯文本；设置页面的“更新日志”一节显示所有版本，内容读自插件包自己的 CHANGELOG.md）。完整的设置列表、各项的取值和例子见插件包里的 README.zh.md。

## 语义检索（可选）

关键词检索找不到换了说法的问题。安装附加插件 [dsh-feiyu-memgate-embed](https://github.com/N0rmal-114/feiyu-memgate/tree/main/plugins/dsh-feiyu-memgate-embed)，在本机只用 CPU 运行向量模型（Windows 上需要 Microsoft Visual C++ 2015-2022 运行库 x64，大多数 Windows 已经装有）。模型就绪后 `auto` 自动换成 `local`，已有的记忆会在后台复制到向量存储里，进度看 `/memgate status`。比模型输入上限长的记忆只按开头部分被检索到，全文照样保存和返回（向量插件的设置 `model.overflow` 改成 `reject` 则拒收）。每种检索方式的记忆分开存放。

设置页面的“本地向量模型”一节列出每个模型的档位、下载大小、运行内存（向量插件实测的模型进程内存，例如 bge-small-zh-v1.5 约 190 MB，不是文件大小）、语言和许可，按“下载并启用”即可：

1. 没装向量插件时，页面先说明要从 npm 安装什么（含原生二进制的 node-llama-cpp，CPU 版约 90 MB，Windows 和 Linux x64 上最多约 740 MB），你确认后才通过宿主的插件管理器安装。
2. pnpm 会拦下 node-llama-cpp 的安装脚本，这时什么都还没装。允许：重新安装并启用。拒绝：DSH 没有按钮，页面会说出配置的 `pnpm-workspace.yaml` 的实际路径，把 `allowBuilds` 下的 `node-llama-cpp: set this to true or false` 改成 `node-llama-cpp: false` 并保存，再按一次按钮即可装好并启用。插件不会替你允许脚本，也不改配置里的文件。
3. 下载、校验、启用模型。关掉页面或重启 DSH 不会丢失进度，中断的下载可以继续。

已经装了但没有启用的向量插件（例如停在安装脚本上的 `dsh plugin add` 之后），按钮会通过插件管理器启用它。各种失败都会说明原因和怎么办；引擎加载不了（状态显示 `runtime-missing`）时，在 Windows 上安装上述运行库后重启 DSH。

## 混合检索（可选）

`retrieval.hybrid` 打开后，语义检索方式（`endpoint`、`local`，以及 `auto` 选到 `local` 的时候）对每个查询同时做关键词检索和语义检索，并合并结果；在 `keyword` 下不起作用。它用的向量存储文件和不开它时相同，旁边多一个关键词索引文件（`memories-<store id>-keywords.db`），所以开或关都不会丢记忆：网关启动之前，插件先让索引和向量文件一致，开启后的第一次启动由已存的文本建立索引（每次启动最多 60 秒，网关照常启动，下次启动接着做）。遗忘相关文件和复制进度文件的名字不变。

测量依据，来自网关自己的基准（用 bge-m3；这次没有为本插件重新测量）：Hit@5 在 PerLTQA（中文，8,588 道题）上混合 95.0%、关键词 87.3%、向量 83.3%；在 LoCoMo（英文，1,535 道题）上混合 58.0%、向量 51.6%、关键词 36.4%；在项目自己的题库（160 道题）上混合 96.7%、向量 98.3%。分数线是用 bge-m3 选的，换别的模型用同一组分数线，没有测量过。表格见[公开数据集](https://github.com/N0rmal-114/feiyu-memgate/blob/main/README.md#公开数据集perltqa-与-locomo)。

## 数据与隐私

- 默认模式下一切都留在你的电脑上。网关只监听 `127.0.0.1` 的随机端口，令牌每次启动随机生成，只在内存里。只有你在设置页面或用 `/memgate install` 安装向量插件或模型时才会下载：宿主的插件管理器从 npm 取向量插件，向量插件下载模型。
- 记忆是普通的 SQLite 文件，插件不加密。打开 `retrieval.hybrid` 时还多一个关键词索引 `memories-<store id>-keywords.db`，里面是同样的文本。删除全部数据：退出 DSH，删除 `<DSH home>/data/feiyu-memgate/`（改过 `gateway.dataDir` 的删那个文件夹）。
- `endpoint` 方式下，每条保存的记忆的文本和每次召回的查询，都会发给你配置的向量接口。
- 召回的记忆是提示词的一部分，会发给这段对话使用的模型服务。
- 每次召回和保存记忆的请求都带一个 `context` 标记，写明请求来自 DSH，以及由什么触发。标记里只有固定的几个值，没有对话内容，也没有任何编号。内置网关不读它；自己部署网关时，自己写的召回步骤和写入守卫可以用它。标记是 `channel: 'dsh'` 加下表里的一个 `via`：

| `via` | 由什么触发 |
|---|---|
| `turn` | 每一轮的自动召回 |
| `search` | `memgate_search` 工具 |
| `followup` | 回复之后再查的一次 |
| `tool` | `memgate_remember` 工具 |
| `capture` | 自动记录 |
| `trial` | 设置页面的“试一下召回” |

## 试一下召回

设置页面“检索”标签页的最后一节“试一下召回”用来查看一句话会召回什么：输入一句话，点“试一下”，页面列出网关为这句话查到的记忆、每条的分数，没给出的记忆还会写明是在哪一步去掉的（低于分数线、和最相关的一条差得太多、没有读到原文、太长、脱敏后没有内容、和前面一条重复、超出字数预算、带有排除标记、超过每次最多的条数、时间不够）。

- 这句话发给网关的 `POST /v1/explain`，请求和一次召回相同，标记里的 `via` 是 `trial`。网关需要支持 `explain`，并在这个客户端的配置里打开：内置网关由插件打开；外部网关需要在配置里给这个客户端加 `explain = true`，否则页面提示不支持。
- 试一下不改动任何记忆，也不算作一次使用。它不碰对话的状态：已给过的记忆、对话池、相关性检查和状态里的计数都不变。
- 这句话先按自动召回的办法处理。太短或只是一句应答的，对话里不会为它召回，页面会这样说明。
- 记忆原文只显示在所有者的设置页面里，不写入日志。
- 页面显示的是网关的结果，不含网关回答之后插件自己做的事：对话里，插件还会跳过历史里已经给过的记忆（`advanced.skipRepeats`），按 `advanced.maxNewPerTurn` 限制每轮的新记忆条数，打开相关性检查（实验功能）时再让模型筛一遍。所以对话里实际给出的，可能比这里“会给出”的少。

## 限制

- 关键词检索找不到换了说法的问题：在网关自己的基准测试里，55 个换了说法的问题一个都没有交出正确的记忆。见[基准测试](https://github.com/N0rmal-114/feiyu-memgate#基准测试)。
- 记忆块留在历史里，上下文会变长。记忆块还在的时候，`advanced.skipRepeats` 避免同一条记忆再被加一次。
- 相连的记忆只量过一次：一个嵌入模型（bge-m3）、48 句编出来的留出闲聊（一道题约两个点）、网关自己的测试工具，没有在真实的聊天里验证过。别的模型沿用同一个门槛（0.60），没有量过。用 `keyword` 时没有变化。每顺着一条记忆，要把已存的向量多扫一遍。
- 回复后再次召回和对话池是原型，只做过离线测量：在项目自己的留出闲聊测试集上（闲聊、记忆和回复都是语言模型写的，一个嵌入模型），拿回复当查询再查一次，直接相关的那条记忆交出去的比例是 72.2%，原来是 61.8%；和它相连的记忆是 60.7%，原来是 44.1%，最多多加两条记忆（[测量记录](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-recall-with-a-model.md)）。没有测过的：真实的聊天、对模型回复的影响、真实宿主上的压缩。对话池另外量过，也是离线的：用语言模型写的多轮对话脚本，每隔三轮模拟一次压缩（[测量记录](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-sessions.md)），在回到前面话题的那些轮次里，需要的记忆摆在模型面前的比例，留出的对话上是 63.9%，原来是 44.4%。一条记忆给出之后约五轮内算仍在谈论中，你的消息提到它或回复用到它则更久；“用到”按相同的字句判断，所以模型硬用上的记忆也会被加强。再查一次得到的记忆晚一轮才到，第二个块里可能有和新消息无关的记忆。两项设置都关着时，这一条都不适用。
- 近期池会在数据文件夹里写 `recent-pool.json`（最多 12 条记忆的文字、日期、来源标签和强度，对话编号和时间）：这是记忆库之外插件唯一写下记忆文字的地方。在记忆库里被遗忘或被取代的记忆，在文件被覆盖或 `advanced.recentDays` 天过去之前仍可能被带进新对话。“上一个对话”就是最后一个别的、用这个插件结束过一轮的对话，这个宿主上的所有对话都算同一个人的。只做过离线测量，用的是语言模型写的脚本化对话和回复、一个嵌入模型（[测量记录](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-18-sessions.md)）：在回到前面对话却不点名那条记忆的轮次里，需要的记忆摆在模型面前的比例从 47.2% 到带三条记忆后的 80.6%（留出的对话；开发用的对话是 36.1% 到 72.2%）。没有在真实的聊天里验证过。
- `advanced.blockTone` 和 `advanced.maxNewPerTurn` 只做过离线测量（[设计说明](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-21-noise.md)）：照常说法下回复闲聊时 30% 到 37% 用上无关记忆、无关寒暄时 50% 到 63%；strict 说法下降到 6.5% 到 12.7% 和 2.6% 到 4.8%，用上有关记忆的回复从 84% 到 90% 降到 70% 到 77%，所以 `strict` 也让模型少用有关的记忆。每轮最多三条新记忆使每轮到达的无关记忆少 13%，248 轮里有 2 轮少了需要的记忆。数据是语言模型写的闲聊和记忆、一个小模型的回复和判断，“用到”按相同字句判断；量过的是对写回复的模型的指示，插件里的这句话是改写，没有单独量过；没有在真实聊天里验证。
- `advanced.relevanceCheck` 只做过离线测量（[设计说明](https://github.com/N0rmal-114/feiyu-memgate/blob/main/docs/design/2026-11-21-noise.md)，括号里是开发用的那一批）：交出去的记忆里有关的占比从 36.2% 到 77.6%（35.3% 到 79.9%）；有关的记忆留下 91.0%（87.6%），无关的留下 14.9%（12.0%）；直接相关的那条在 89 例里留住 87 例（76 例里 75 例）；和记忆都无关的寒暄里一条都没留的占 66.7%（83.3%），只靠查询自己安静的是 20.8%（12.5%）。一个小模型分批挑的，闲聊和记忆是语言模型写的，延迟和费用没有量，没有在真实聊天里验证。有候选记忆的每一轮在回复之前多一次模型调用（更慢，按该模型计费），消息和候选记忆发给该模型的提供方（默认是对话本身的）。宿主模型接口的用法照宿主源码和已安装的版本写成，没有在真实宿主上跑过。第二个块不检查。
- 没有在真实的聊天里验证过。0.3.1 的这些改动（不重复给记忆、今天的日期和“多久以前”、记忆的写法说明、自动记录的过滤、召回失败的说明）由单元测试和模拟宿主的测试覆盖，没有在和真实模型的对话里验证过。模型是否照新的说明去做、日期和“多久以前”是否让回答变好，没有测量。“今天”是这台电脑上的日期。
- 只有模型选择保存的记忆才存在，除非打开自动记录。
- 每日写入上限在内存里计数，按 DSH 进程计，网关重启后重新开始。
- 设置页面依赖宿主里仍在变化的界面接口；没有它，用 `/memgate` 或 profile 文件也能改全部设置。
- 真实环境测试：在 Windows 11 上已安装的 DeepSeek Harness 0.2.2-rc.1 里，用一个隔离的配置测过：插件能加载，内置网关用 PATH 上的 Python 启动，设置页面能显示和保存，状态接口和模型接口只回应所有者的会话，聊天命令可用；装上向量插件和 bge-small-zh-v1.5 后用的是 local 检索方式，换了说法的问题能找到对应的记忆。通过设置页面从 npm 安装向量插件也测过，测的是拒绝依赖的安装脚本这条路：向量插件装好并启用，模型下载完成，检索方式换成 local（允许脚本的那条路没有跑过）。0.3.0 的混合检索也在一个隔离的配置里跑过，向量接口用的是本机的一个替身服务，不是真实模型：`endpoint` 方式打开 `retrieval.hybrid` 后，网关以混合存储启动，关键词存储里的记忆被复制到向量文件和关键词索引两边；宿主停止时从向量文件里删掉一条，下次启动索引同步去掉了这一条。在这个从源码目录链接插件的配置里，设置页面的表单显示“宿主暂未提供此插件的设置表单”（0.2.0 在这里也是这样），所以新开关在表单里的显示没有实际看到，开关是通过 profile 文件设置的。没有测过：macOS 和 Linux 桌面、桌面应用自己的窗口（用的是同一宿主的 web 配置）、和真实模型的对话（自动召回和两个工具只在测试里和对着网关测过，没有在实际聊天里用过）。
- 当前版本是 0.3.2，每个版本改了什么见[更新记录](https://github.com/N0rmal-114/feiyu-memgate/blob/main/plugins/dsh-feiyu-memgate/CHANGELOG.md)。0.3.2 改了一项默认行为：用语义检索时，记忆块里可能多出最多两条和最先查到的两条相连的记忆，用 `advanced.linkedRecall` 可以关掉。0.3.1 改了几项默认行为，每一项都有开关：不重复给同一条记忆（`advanced.skipRepeats`），记忆块写明今天的日期和每条记忆是多久以前的事（`advanced.showAge`），召回失败时告诉模型（`advanced.failureNote`），自动记录跳过无关紧要的消息（`advanced.captureMinChars`）。保存的记忆带上本地时间，内置网关也更新到同一版本。

## 遇到问题

先运行 `/memgate status`。找不到 Python 时安装 Python 3.11 或更新，或设置 `gateway.python`；网关起不来时看数据文件夹里的 `gateway.log`。关掉整个插件：在插件页面关掉它的那一行；只关一项功能：`/memgate off <功能>`。
