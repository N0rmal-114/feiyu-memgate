# 聊天场景的测试题

`bench/data` 和 `bench/dev` 里的题目都是提问：“主人的猫叫什么”。聊天里更常见的是另外两种情况，那两套题量不出来：

- **闲聊**。主人说“最近天气有点热”，没有在问什么。一个了解他的朋友会想起“他很怕热”“他喜欢吃冰淇淋”，再顺着想起“上次他的冰淇淋掉在了地上”。这里要找的记忆和这句话没有相同的词，有的还要经过另一条记忆才连得上。
- **追问**。前面几轮已经在聊一件事，主人接着说“那后来呢”“它多少钱来着”。单看这一句不知道在问什么。

这一套题专门量这两种情况，外加“该安静的时候是不是安静”。

## 数据是怎么造的

每个“世界”是一个虚构的人和关于他的 60 条记忆，记忆是按“簇”写的，这样标注有据可查，不靠感觉：

- 一个**簇**围绕一个具体的东西：一只宠物、一种吃的、一个人、一个地方、一件电器、一个习惯。每个簇有一条**事实**（“主人喜欢吃冰淇淋，最喜欢香草味的”）和一到三条**经历**（“主人上次在公园吃冰淇淋的时候，冰淇淋掉在了地上”）。经历里一定出现这个簇的名字或别名，别名由事实那一条引入（事实说“主人养了一只橘猫，名字叫年糕”，经历可以只说“年糕”）。
- 另有一些不属于任何簇的**零散**记忆，作为干扰。

题目分四类：

| 类型 | 是什么 | 标注 |
|---|---|---|
| `remark-assoc` | 一句闲聊，不出现簇的名字，但按日常的常识会让人想到它 | `direct`：这个簇的事实；`chain`：这个簇的经历 |
| `remark-named` | 一句闲聊，直接提到了簇的名字或别名 | `direct`：这个簇里的全部记忆 |
| `follow-up` | 两到四轮对话之后的一句短话，单看这一句不知道指什么 | `direct`：能接上这句话的那一两条记忆 |
| `quiet` | 一句和所有记忆都无关的闲聊 | 都为空：什么都不交才对 |

每道题另有 `also_ok`：不在标注里、但交出来也说得过去的记忆，不算杂讯。`why` 用一句话写明联想的理由（“热，想吃冷的”）。

## 文件

```text
bench/chat/
  validate.py          检查一个世界文件是否符合上面的规则
  dev/<世界>.json      开发集：选规则、调参数只看这里
  test/                测试集：冻结，不看着它调任何东西；不在仓库里
```

一个世界文件：

```json
{
  "world": "dev-teacher",
  "persona": "一句话说明这个人是谁",
  "clusters": {"c01": {"entity": "冰淇淋", "terms": ["冰淇淋"]}},
  "memories": {
    "m001": {"text": "主人喜欢吃冰淇淋，最喜欢香草味的", "date": "2026-06-02", "cluster": "c01", "role": "fact"},
    "m002": {"text": "主人上次在公园吃冰淇淋的时候，冰淇淋掉在了地上", "date": "2026-08-15", "cluster": "c01", "role": "episode"},
    "m050": {"text": "主人的手机屏幕摔裂过，一直没去换", "date": "2026-08-20", "cluster": null, "role": "filler"}
  },
  "cases": [
    {"id": "r01", "type": "remark-assoc", "history": [], "message": "最近天气有点热",
     "direct": ["m001"], "chain": ["m002"], "also_ok": [], "why": "热，想吃冷的"}
  ]
}
```

`history` 是这句话之前的对话，每项是 `{"role": "user" 或 "assistant", "content": "..."}`；只有 `follow-up` 需要。

检查：

```bash
python -B bench/chat/validate.py bench/chat/dev
```

## 规则

和 `bench/dev`、`bench/data` 一样：规则和参数只在开发集上选，选定之后才在测试集上跑一次，跑完不再改。数据全部虚构。
