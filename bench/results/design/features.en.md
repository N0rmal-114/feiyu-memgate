# Functional facts about the benchmarked projects

> Date: 2026-11-17. Every cell is only about the version in the "Version benchmarked" column; the projects may have changed since.

This table puts the thirteen projects of the benchmark side by side (this project in the first row) and holds functional facts only: what form it takes, how it retrieves, whether the default write calls a language model, whether it merges, rewrites or tidies memories in the background after a write, what it delivers by default, whether it forgets or decays, and its licence. It is not a score and does not rank anything. Retrieval numbers are in the [benchmark summary](../summary.md); how each system is set up and called is in the README of its adapter directory (`bench/adapters/<system>/README.md`). This project's own design self-check is in [self-check.en.md](self-check.en.md).

Sources: [bench/systems.json](../../systems.json), each adapter's README, the per-system notes in the [benchmark summary](../summary.md), the reports under [research/reports/](../../../research/reports/) (Chinese), and the project's own public repository page. Anything not found there is written as "not confirmed", never guessed. Machine-readable version: [features.json](features.json).

"Injected" means the memory is put into the prompt automatically before the model answers; "the model calls" means memories appear only when the model decides to call a retrieval tool.

## Notes

- meow-memory is published on npm as `meow-memory`; its GitHub repository is called dsh-meow-memory.
- For most projects the benchmark bypassed the default language-model write path (verbatim writes) and measured only retrieval and delivery; the "Default write calls a language model" column describes the project's own default, not what the benchmark did. How each system was actually written to in the benchmark is in its adapter README.
- OpenViking's forgetting or decay: the origin project's design notes ([docs/design/2026-11-12-origin-audit.md](../../../docs/design/2026-11-12-origin-audit.md), Chinese) mention event time decay and on-demand consolidation; the benchmark did not use or verify them, so the cell says "not confirmed".
- In dsh-fish-memory and dsh-prime-memory the product's write path lets a model decide what to store (through the remember tool in the first, by distilling conversation in the second); the benchmark writes every memory verbatim and does not measure that choice. In dsh-soul-md the benchmark writes each memory as one topic file, while a product topic usually merges several entries.
- The two `hindsight-llm-*` configurations of Hindsight run the server's default path (a model extracts facts and consolidates them into observations); `hindsight-chunks` uses no model and stores each memory as one verbatim chunk. The reflect text the plugin injects by default is written by a model and is not a list of memories; it was not measured, the server's recall was.
- The "Merging, rewriting and background upkeep" column describes what the project itself does. The benchmark measures retrieval and delivery only, and most of the features in that column did not run; which parts were measured is in ["What the scores do not cover" in the README](../../../README.en.md#what-the-scores-do-not-cover).
- The two `expand-*` configurations of dsh-fish-memory run the plugin's own background keyword expansion with a model (writes stay verbatim, the model only adds retrieval words).
