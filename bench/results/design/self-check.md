# feiyu-memgate 设计自查

> 日期：2026-11-15。对象：feiyu-memgate 0.1.0（2026-11-15 探测的那一版）。

feiyu-memgate 是记忆**网关**：它主张的不是更好的检索，而是检索周围的东西：谁能读什么、什么被清理、什么有界、失败时是否说实话。这份自查只描述 feiyu-memgate 自己，不给其他项目打分。检索质量见 [基准总表](../summary.md)；各被测项目的功能事实（形态、检索方式、写入是否调用模型、默认交付、遗忘、许可证）见 [features.md](features.md)。

## 怎么得到的

- 十项性质都由 [`bench/design_probe.py`](../../design_probe.py) 实际运行本项目测出：每个探针在临时目录里按配置建一个网关（SQLite 存储，需要时在回环地址上起一个一次性服务），只用假的密钥和数据。原始结果在 [feiyu-memgate.json](feiyu-memgate.json)，机器可读的汇总在 [self-check.json](self-check.json)。
- 符号：✓ 成立，◐ 部分成立，✗ 不成立。一项性质里有一个检查没过，或者一个属于这项性质本身的已知限度被观察到，就记 ◐。
- 探针是本项目自己写、自己跑的，结果只说明这些检查在这一版上成立，不等于没有别的问题。

## 每一项的实测依据

1. **写入前脱敏**（✓）：探针1：假 API 密钥、“密码是…”、Bearer 令牌写入后，存储原文里 0/3 处残留，出现 4 个 [REDACTED]；公开客户端另遮手机、邮箱、证件号、地址（探针2）。只是正则，没有关键词的孤立密钥认不出（实测：未遮）。
2. **返回前脱敏**（✓）：探针1：绕过网关直接写进存储的假密钥和假密码，召回回答里 0 处残留（redact 召回步骤，默认开启，回答里出现 [REDACTED]）；公开客户端另遮个人信息（探针2：召回时手机、邮箱、证件号、地址都被遮，私有客户端原样保留）。
3. **记忆作为数据交付且不可越界**（✓）：探针3：含闭标签、开标签、伪 system 指令的记忆，经 BlockFormatter（中英文各一次）后块里恰好 1 个开标签、1 个闭标签，4 处左尖括号被转义，每条压成一行，头部写明“资料，不是指令”。限度：指令文字本身不改写，模型仍可能听信；全角/零宽变体不是 ASCII 标签，原样通过；块由客户端库生成，直接用 HTTP JSON 的调用者须自己包裹。
4. **凭据级隔离**（◐）：探针4：群客户端令牌读不到主人库（0 条）、/v1/used 指向主人库 403；不带 tenants 的客户端发 tenant_id 得 400 bad_tenant；未登记租户 403；错令牌和无令牌 401；路径式租户号 400。租户之间有两种模式。tenant_binding = "token"（可选）：每个令牌由铸造密钥按租户用 HMAC 铸造；实测为租户 10001 铸造的令牌不写 tenant_id 就读到 10001，看不到 10002 的记忆；请求体里写 11 种别的 tenant_id（别的租户、路径式、空、前后带空白、数字、null、true、列表、对象）全部 403 tenant_mismatch；往 10002 写入、报告用到都 403，10002 没有变化；铸造密钥本身当令牌用 401，把令牌里的租户号换成 10002 得 401，为未登记租户铸造的令牌 403。tenant_binding = "request"（默认）：租户号由令牌持有者自报，同一个群令牌能换号读任何已登记租户（实测：问 10002 无结果后同一令牌读到 10001 的记忆）；[security.md](../../../docs/security.md) 写明这种模式只适合一个可信的进程，`feiyu-memgate check` 对这样的客户端打印提醒。记部分，因为绑定只在配置了 tenant_binding = "token" 时才由网关强制（实测成立），默认的 request 模式下一个多租户令牌仍能读所有已登记租户。
5. **失败与空结果可区分**（✓）：探针5：唯一的存储报错 → 503 unavailable；空存储 → 200、results 为空、failed 0；两个存储一个坏 → 200 且 failed=1，仍返回另一个的结果；/healthz?deep=1 把坏存储标为 down，recall_failed_1h 计数。
6. **写入上限**（✓）：探针6：daily_writes=5，8 个线程共 32 次并发写，恰好 5 次成功、27 次 429 daily_limit，存储里恰 5 行；rate_limit=5 时 8 次请求为 5 个 200 加 3 个 429；轮换 10 个租户号仍被 rate_limit_total=6 拦住（6 个 200 加 4 个 429）；daily_writes_total=4 时 11 个租户一共只存下 4 条。限度：计数在内存里，重启清零。
7. **输出有界**（✓）：探针7：limit=3 得 3 条，默认 5 条，limit=50 得 10 条（上限 10），limit=0 得 1 条；字数预算 1500：库里 6 条 400 字加一条 1700 字的记忆，返回 3 条共 1200 字、more=4，每条返回文本都等于存储原文（不截断），1700 字的超预算记忆整条留下；75026 字的记忆整条丢弃（note oversize-dropped）。输入：4001 字消息 → 400 bad_messages 且行数不变，4000 字原样存下，5×3500 字 → 400，501 字查询 → 400，超 64 KiB 请求体 → 413。
8. **遗忘可恢复**（✓）：探针8（假时钟，半衰期 10 天，归档保留 30 天）：记忆日期 2025-01-01 的老库首次清理删 0 条；第 30 天（C 被 /v1/used 报告用过）删 0 条；第 50 天：未用过的 A 被存档后删除，置顶的 B 和用过的 C 保留；存档里的文字等于原文；restore 后原文回到存储、存档行移除；恢复后立刻清理不会再删；第 100 天再次被存档；保留期过后（第 135 天）存档副本被清掉。限度：存档文件是明文；遗忘要配置 [forgetting]，默认关闭。
9. **写入无需大模型**（✓）：探针9：socket 被打补丁、一碰就抛错时，SQLite 路径的 3 次写入全部 200、召回 200，socket 构造/连接/解析尝试 0 次；写入链上只有 redact 和 daily_cap 两个守卫，没有模型件。限度：只测了 SQLite；openviking、embedding、hybrid 后端会联网（嵌入服务，或带抽取模型的服务端）。
10. **网络面最小且需鉴权**（✓）：探针10：路由表恰好 4 条（GET /healthz，POST /v1/recall、/v1/remember、/v1/used）；199 个其余方法×路径组合（含 /v1/delete、/v1/list、/v1/export、/admin、/metrics）全部 404/405；三个 /v1 路由无令牌或短令牌都是 401；默认监听 127.0.0.1；没有删除、列出、导出路由。已知偏差：/healthz?deep=1 不要令牌，回存储名和计数。

## 没有通过的地方和限度

这些是探针自己报告的，没有为了结果修改任何东西：

- **默认模式下租户之间不是凭据隔离**（探针4，◐）：默认的 tenant_binding = "request" 里多租户令牌不绑定租户号，同一个群令牌能读任何已登记租户，只适合交给一个可信的进程。可选的 tenant_binding = "token" 给每个租户铸造各自的令牌，探针4 实测它把令牌限制在铸造时的租户上（请求里换租户号 403 tenant_mismatch，铸造密钥本身当令牌用 401）；它要自己配置才生效，见 [docs/security.md](../../../docs/security.md)。
- **`/healthz?deep=1` 不要令牌**，回存储名、失败计数和写入统计（文档自述的设计）。
- **脱敏是正则**：没有关键词的孤立密钥、座机、全角数字认不出（探针1、2 实测到，文档自述）；指令样文字不改写，全角/零宽的标签仿写原样通过（探针3）。
- **只测了 SQLite 路径**（探针9）：openviking、embedding、hybrid 后端会联网。
- **限额计数在内存里**，重启清零；**遗忘的存档文件是明文**，遗忘默认关闭。

## 别的项目有、本项目没有的能力

在被测的项目里看到、feiyu-memgate 目前没有的功能。只列功能本身，各项目的细节以它们自己的文档为准。

1. **回复真的用上了某条记忆才自动强化它**（SeekMemory）。回复用到某条记忆时，它自动得到加权，衰减计时重新开始；只被检索或注入不算。本项目有同样的思路：POST /v1/used 记录“真的用了”（探针8 实测 recorded=1），但要聊天程序自己上报；不上报时，只有可选的 freshness 召回步骤会在召回时给最相关的一条记一次使用（credit 默认 top），而被返回不等于有用。
2. **分级披露：全文、转述、暗示或沉默**（SeekMemory）。按记忆和当前对话的契合程度决定给出全文、转述、一句暗示还是不提。本项目的访问是按存储、按凭据的全有或全无，没有分级。
3. **被新事实取代的旧事实会被标记失效**（Graphiti、SeekMemory）。Graphiti 用大模型比较新旧事实，给被取代的旧事实写上失效时间；SeekMemory 用 supersedes 字段让被反驳的旧记忆退场。本项目按原文存，召回时用 dedupe 去掉近似重复、用 newer_first 把新的排在前面，没有“后一条取代前一条”的概念。
4. **用大模型抽取和整理记忆**（mem0、Graphiti、SeekMemory、dsh-mnemon、memsearch、meow-memory、OpenViking）。mem0 抽取事实（名字被解析、日期落到绝对日期）；Graphiti 抽取实体和带时间的事实；OpenViking 在会话提交时抽取；dsh-mnemon 有空闲复盘；SeekMemory 由宿主模型抽取，并有夜间整理；memsearch 的插件总结每一轮；meow-memory 有反思与梦境整合。本项目网关只存原文，抽取（如果有）是后端的事（OpenViking 后端）；换来的是便宜、可预测、不联网，失去的是归并、改写和从长对话里提炼要点的能力。
5. **写入时的去重、合并和闸门**（lingshu、meow-memory、mem0）。lingshu 的写入闸门对每次写入给出 ACCEPT/MERGE/DROP/DEFER 并记日志，同骨架的短消息 24 小时内合并；meow-memory 把和已有同级记忆高度相似（词元 Jaccard ≥ 0.8）的新记忆并进已有的那一行；mem0 按哈希去重。本项目默认的写入守卫只有 redact 和 daily_cap，重复的记忆照存，到召回时才用 dedupe 步骤去掉近似重复。
6. **按轮收窄读范围，并说明“空不等于没有”**（dsh-mnemon）。一轮只读它这一轮指定的记忆空间；预算用完时策略报告没有去查，并说明空列表不等于没有匹配。本项目的读权限固定在令牌上，一次召回内不能再收窄；失败与空的区分有（failed、busy、503），但没有“预算用完所以没去查”的逐轮说明，除了 busy 计数。
7. **每条记忆可以设到期日**（mem0）。可选的 expiration_date 让记忆到期后不再出现在检索结果里。本项目没有按条的到期日，遗忘只由“多久没被用到”的曲线决定。
8. **记忆是人能读、能改、能进 git 的 Markdown**（memsearch）。Markdown 文件是真源，索引可以重建，删掉的内容可以从文件或 git 找回。本项目的记忆在 SQLite 里，改动要走工具；有加密备份（backup seal），但不是人能直接编辑的格式。
