# 开发集（dev-v1）

数据版本：`dev-v1`

这是一份比 `examples/eval`（46 条记忆、30 个问题）大得多的开发集，**只用来挑选默认阈值和其他默认参数**：
小开发集看不出严格阈值的代价（漏答），所以默认值在留出集上泛化很差。这份集合让阈值的取舍在一个够大的样本上可见。

**它从来不用来报告结果。** 对外的数字只来自留出集 `bench/data/`，在默认值定下之后才跑一次。
开发集上的任何分数都不能当作系统表现写进报告或文档。

**这份集合是在没有接触留出集的情况下写成的**：写作者没有打开过 `bench/data/memories.json` 和
`bench/data/queries.json`，只读了 `bench/CONTRACT.md`、`bench/data/README.md` 和 `bench/data/validate.py`
里对格式和构造规则的描述。人物、群、事件、问题全部是另行编的，与留出集的虚构人物没有关系。

## 内容

- `memories.json`：160 条记忆，格式 `{"d001": {"text", "date", "source", "kind"}, ...}`，编号按日期排序。
  - 虚构的主人：汇川口内河船闸的值班员，离异，带着上初中的女儿小满；养一条老黄狗、在河滩养几箱蜂、
    修老收音机、学手风琴，母亲住在老家石埠村，姐姐在外省。日期分布在 2025-01 到 2026-10。
  - 其中 40 条来自虚构的群聊“嗡嗡养蜂小队”（`source` 为 `group`，其余为 `private`）：五个昵称成员、
    暗号和笑话、聚会、谁教会了机器人什么。
  - 文本是第三人称短句或事件笔记，15 到 80 个汉字。
- `queries.json`：110 个问题，`{"q001": {"query", "expect", "type", "stale"?}, ...}`。

  | type | 数量 | 说明 |
  |---|---|---|
  | lexical | 30 | 问题沿用了答案记忆里的关键词 |
  | paraphrase | 38 | 同一个意思换了说法：同义词、描述代替名字、口语；尽量少和答案共用字 |
  | updated | 12 | 事实被更新过：`expect` 是新记忆，`stale` 是被取代的旧记忆（相隔至少 3 个月） |
  | quiet | 30 | 记忆里没有答案，`expect` 为空；一半和已有记忆共用主题词，一半毫不相干 |

  每个可回答的问题只有 1 条期望记忆。问题用“我”指主人，用“群里”指群聊。
- `validate.py`：与 `bench/data/validate.py` 相同的检查（编号、数量、引用、重复、长度、日期、更新间隔），
  数量换成本集的数字；字符二元组重叠只报告不强制。运行：`python bench/dev/validate.py`。

## 怎么写出来的

全部由人手写，没有用模板或随机脚本生成。

1. 先定一个前后一致的虚构人物和一个虚构群，再按话题写：同一个话题写 3 到 6 条用词相近、事实不同的记忆
   （几种面食、几次割蜜、几次旅行、几位医生或长辈、群里五个人各自爱吃的蜜、几台收音机），
   检索不但要找到话题，还要把对的那条排在最前。
2. 12 组“更新”：同一件事先后两条记忆（班次、住处、戒烟、喝茶、蜂箱数、女儿上学方式、狗的伙食、学琴方式、
   课外班、站长、群里看蜂的日子、群主），新的取代旧的，日期至少相隔 3 个月。
3. 问题按用户对机器人说话的口气来写。写完后用字符二元组重叠检查，再逐条通读：期望记忆是否是近邻里
   唯一最好的答案，quiet 题是否被某条记忆答出，只拿到这批记忆的人能否答出每一道 paraphrase 题。
   通读后改写了若干题（答案与近邻有重合、或与答案共用字过多的）。
4. 编号用 `d###`，与留出集的 `m###` 区分，避免两套数据混淆。

## 规则

- 全部虚构：人名、昵称、地名（汇川口、石埠村、鹭鸶洲、雾凇岭、云崖寨等）都是编的。
- 没有真实人物，没有品牌，没有电话号码、住址、证件号。

## 局限

- 单一作者、单一虚构人物、全部中文短句；文风比真实对话整齐。
- 期望答案由作者一个人判定；paraphrase 的“改写程度”只用字符二元组重叠衡量，不等于语义距离。
- 样本仍然不大（最小的题型只有 12 题），拿它选默认值是为了避免明显的偏差，而不是做精细调参。
