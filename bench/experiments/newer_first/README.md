# newer_first：在开发集上选默认值

`newer_first` 是一个可选的召回步骤：同一次请求里，分数在最高分 `band` 倍以内的候选中，带日期的按“新的在前”交换分数
（分数的多重集合不变，不丢任何候选）。本目录用 `bench/dev`（只用开发集，没有碰 `bench/data`）选 `band` 的默认值。

## 怎么复现

候选列表只算一次，每个网格点在真实的网关和召回步骤上重放（和 `bench/dev_eval.py` 同一套）。向量后端要 `fmg-bench` 里的嵌入服务：

    python bench/experiments/newer_first/run.py collect --backend embedding --embed-url URL --out embedding.json
    python bench/experiments/newer_first/run.py collect --backend hybrid --embed-url URL --out hybrid.json
    python bench/experiments/newer_first/run.py report --collect-sqlite --cand embedding=embedding.json --cand hybrid=hybrid.json

## 事先定好的规则

网格：`band` 取 0.80、0.85、0.90、0.95、1.0（1.0 = 不用这个步骤）x `related` 取 0、0.15、0.3；步骤插在默认一套的 `relative_score` 后面。
在每个后端上，“所有可回答的问题里，第一条交付的是期望记忆”的题数不比不用步骤时少超过 1 题的网格点才合格；
合格的点里取三个后端的 (a) 平均值最高的；平手取更大的 `band`（更温和），再取 `related` = 0。
如果没有任何点在任一后端上改善 (a)，步骤保持可选、`band` 取 0.9。

指标：(a) 更新类问题，网关实际交付的列表里新记忆排在旧记忆前面（或旧记忆没出现），只算新记忆被交付的题；
(b) 同样的判断，在没有任何阈值的前 10 名排序上（只跑步骤的 `prepare`），只算新记忆在前 10 名里的题；
(c) 全部可回答问题的“第一条正确”、交付命中、精确率、安静率（后三项不应变化）。

## 结果

只有 12 道更新题（其中新记忆被交付的：sqlite 0 题，embedding 8 题，hybrid 9 题），数字是原始题数，差一两题就是几十个百分点，只能当取向，不能当定论。
sqlite 上更新题的得分大多低于它的默认分数线 0.30，新记忆一条都没被交付，所以 (a) 无从算起。
(b) 在原始排序上是 3/9，步骤对它不起作用：旧记忆排在前面的题里，新记忆的分数都低于最高分的 0.8 倍（最接近的 0.78），落在整个网格的带宽之外，
关键词分数的差距比这个步骤能管的大。
sqlite 在 (a) 上记 0，对所有网格点相同，不影响选择。

## 说明

- `related` 用的是字符二元组的 Jaccard 重叠（和 `dedupe` 同一个度量）。这 12 对新旧记忆的重叠只有 0.02 到 0.14，
  所以 `related` 取 0.15 和 0.3 时一对也不会交换，步骤等于关掉。这个守卫在这套数据上没有可用的取值；
  它防的是“两条毫不相干的记忆都得高分”，而开发集里没有这种需要被防的情形可量，所以默认保持关（0）。
- 带 `band` 0.80、`related` 0 的混合后端有 1 道题交付的集合变了：两条候选互换位置后，限制条数把另一条挤了出去。这符合设计（只有 limit 或 budget 才会改变交付的集合）。
- 选出的 0.85 比 0.90 在 embedding 上多对 1 题（(a) 7/8 对 6/8），hybrid 上两者相同；差别只有一道题。
